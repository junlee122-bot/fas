# PC 행동 바 검토 — RimWorld에서 가져올 원리와 IRON DOMINION 적용안

검토일: 2026-09-23. **설계 검토이며 이번 배포에 행동 바 구현은 포함하지 않는다.** 기존 UI 전체를 새 테마로 교체하지 않고, 사용자가 이미 가진 기능을 발견하고 실행하는 경로를 개선하는 제안이다.

## 결론

**도입 권장. ‘하단 고정 분야 메뉴 + 그 위의 선택 대상 명령’ 2계층이 가장 적합하다.** 기존 좌측 메뉴와 지도 선택 카드를 그대로 둔 채 버튼 줄만 추가하는 안은 권하지 않는다. 더 많은 중복 버튼과 가림을 만들기 때문이다.

기술은 맨 아래의 11번째 메뉴에서 찾는 대신 항상 같은 위치에서 보이게 한다. 분야 메뉴는 화면을 여는 기능, 선택 명령은 현재 대상에 대한 행동이라는 차이를 유지한다. 보직 밖의 일은 보기·보고·상신 등 기존 권한 범위로 연결한다.

## 추천 배치

하단 상시 분야 바 예시:

`본부 | 지도 | 작전 | 조직 | 기술 | 생산 | 재정 | 외교 | 더보기`

- 아이콘과 한글 이름을 함께 표시한다. 기술·재정처럼 중요하고 자주 찾는 기능은 ‘더보기’에 넣지 않는다.
- 정보·보건·국정·기록·설정은 더보기와 역할별 고정 구성으로 접근하되, 스파이 보직에서는 정보가 기본 자리를 갖는다. 위치는 주간 중요도에 따라 계속 재정렬하지 않는다.
- ‘기술’에는 진행 중 연구 수와 빈 슬롯을 실제 상태에서 계산해 표시한다. 권한이 없는 사람에게 빈 슬롯을 긴급 결재로 표시하지 않는다.
- 현재 역할에서 접근 불가/상부 권한이면 아이콘만 회색 처리하지 않고 ‘보고’, ‘상부 권한’ 등의 텍스트를 제공한다. 불가 사유는 키보드로도 읽을 수 있어야 한다.
- 다음 주·재생 속도는 당분간 기존 상단에 유지한다. 탐색 메뉴와 시간 진행을 동시에 옮기지 않는다.
- 하단 바 모드에서는 좌측의 같은 전체 메뉴를 동시에 상시 노출하지 않는다. 기존 메뉴 모드는 설정에서 복귀 가능하게 하고, 초기 검증은 선택형으로 진행한다.

그 위에는 현재 선택에 따른 명령 줄을 둔다:

| 선택 대상 | 명령 예시 | 실행 경계 |
| --- | --- | --- |
| 선택 없음 | 현재 업무·진행 상태 요약 | 공격/이동 등 대상 필요한 명령 없음 |
| 거점 | 주둔군, 통제 기록, 통행권 검토 | 조회/협상 화면 열기. 선택만으로 소유권 변경 없음 |
| 아군 부대 | 이동 계획, 공세 계획, 보급 상태, 명령 현황 | 현재 소속·직접 지휘권·원위치 재검증. 공세는 기존 계획실 승인 |
| 함대 | 항로 검토, 호위 계획, 기지 변경, 귀환 검토 | 항속·연료·기지권·진행 임무 확인. 즉시 이동으로 처리하지 않음 |
| 인물 | 상세, 면담 의제, 보직 비교 | 현 보직 권한과 기존 인사 승인 흐름 유지 |
| 연구 | 과제 상세, 진행 슬롯, 장비 개발국 | 첫 단계는 열람만. 시작/중지 직접 실행은 공통 권한 검증 완성 후 |

‘거점 선택’과 ‘부대 선택’을 하나의 오래된 ID로 추정하지 않는다. `kind + id + 현재 화면/소속`을 명시적으로 구분하고, 혼합 다중 선택에서는 공통으로 유효한 행동만 제공한다. 빈 곳을 클릭하거나 카메라를 옮겨도 이미 승인한 공세와 작성 중 초안은 취소하지 않는다.

## 크기와 정보 밀도

- 초안 목표: 상시 분야 바 56–64 CSS px, 선택 명령 줄 76–104 CSS px. 실제 구현 후 PC 화면 측정으로 확정한다.
- 주 행동은 최대 6개. 추가 행동은 명시적 더보기로 분리한다. 가로 스크롤을 기본 조작 방식으로 쓰지 않는다.
- 클릭 영역 최소 44×44 CSS px, 주요 라벨 14–16px, 보조 상태 12–13px를 시작점으로 한다. 그림은 명령 아이콘을 대체하지 않는다.
- `--action-nav-height`, `--context-row-height` 같은 공통 높이로 콘텐츠 영역을 예약하고 지도·카메라·선택 패널의 사용 가능 영역을 함께 계산한다. 화면 위에 fixed 레이어만 추가하지 않는다.
- 지도 위 장식 그림/자동 영상은 넣지 않는다. 강조는 선택, 가능한 행동, 차단 사유, 검토 대기 상태에만 사용한다.
- 1080p/1440p/4K뿐 아니라 125%·150% OS 배율에 해당하는 CSS viewport도 검증한다. 카메라 중심·지도 투영·좌표 데이터는 레이아웃 변경과 별개로 보존한다.

## 실행 안정성

1. 메뉴 이동은 기존 `openGameTab`과 권한별 업무 경로를 재사용한다. 숨겨진 화면의 변경 함수를 바로 호출하지 않는다.
2. 상태 수치·비용·예상 시점은 기존 엔진 assessment에서 읽는다. 바 내부에 다른 비용 계산이나 두 번째 실행 로직을 만들지 않는다.
3. 외교·인사·공세 같은 중대한 결정은 `계획/검토 열기 → 조건 확인 → 기존 승인` 순서를 보존한다.
4. 대상을 바꾸거나 주차·권한·자원이 바뀌면 이전 검토는 재검증한다. 더블 클릭은 한 번만 집행된다.
5. 연구를 바에서 직접 시작하게 하려면 `toggleResearch`에도 보직·기간 진행·슬롯·선행 조건을 다시 검사하는 공통 실행 경계를 먼저 만든다. 첫 단계에서는 연구 화면으로 이동만 허용한다.
6. 모달·튜토리얼·삽화 확대가 열리면 행동 바도 배경과 함께 비활성화한다. Esc는 최상위 UI 한 단계만 닫으며 승인된 명령을 취소하지 않는다.
7. 기존 숫자·문자 단축키는 유지한다. 초기 행동 바는 마우스·Tab/Enter를 우선하고 별도 단축키는 키 충돌 표와 사용자 재지정 구조가 마련된 뒤 추가한다.

## 권장 구현 순서와 합격 기준

### 1차: 분야 바와 기술 상태

순수 탐색 바와 읽기 전용 진행 상태만 구현한다. 기존 사이드 메뉴와 전환 가능하며 저장 스키마/게임 엔진 변화는 없다. 모든 보직에서 권한 의미가 동일하고 기술 화면까지 한 번에 이동해야 한다.

### 2차: 지도 선택 맥락 줄

기존 선택 지역 footer와 명령 링크를 통합한다. 거점/부대/함대/다중 선택을 구분하고 계획 화면을 연다. 거점 선택·카메라 이동·메뉴 전환으로 공세가 취소되지 않는 회귀 검증을 우선한다.

### 3차: 인물·연구 및 사용자 고정 구성

기존 검토 패널과 연결하고, 필요하다면 공통 command descriptor를 둔다. 직접 집행 액션은 권한을 실행 시점에도 검증한 뒤 추가한다. 즐겨찾기와 단축키는 마지막에 제공한다.

합격 기준: 모든 PC 검사 화면에서 바/지도 도구/선택 패널의 겹침 0, 가로 스크롤 0, 기술 진입 한 번, 키보드 포커스 누락 0, 빈 거점 선택 후 이전 부대 오명령 0, 보직 변경/해임/주간 처리 중 권한 우회 0, 모달 뒤 실행 0, 취소·탐색의 자원 변화 0. 클릭 수 감소는 기존 화면과 같은 과업으로 비교하고, 재미나 이해도 개선은 실제 사용자 테스트 전에는 확정하지 않는다.
