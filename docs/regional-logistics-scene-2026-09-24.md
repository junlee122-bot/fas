# 실제 기록 기반 물류 관제판

## 이번 묶음

국정 단계의 `지휘 본부 → 현장 보기 → 물류 현장`을 추가했다. 배치도의 군수 창고/물류 조정실에서도 연결된다. 기존 `산업 → 집하·수송 → 현재 흐름`에는 같은 관제판을 재사용한다.

- 실제 출발 예약·운송·도착·예약 취소 기록을 선택한다.
- 현재 막힌 운송부터 우선 표시하고, 진행 중/보류/도착 필터를 제공한다.
- 품목별 창고·예약·운송 중·이번 주 도착을 분리한다. 다른 장비의 개수를 한 물량으로 합산하지 않는다.
- 각 운송 자체의 출발·도착지를 사용한다. 현재 승인 노선으로 옛 운송 경로를 덮어쓰지 않는다.
- 현재 경로·출발 용량 문제와 지난 결산의 보류 기록을 구분한다. 조건이 복구되어도 실제 재개는 다음 결산에서 확인한다.
- 기록 열기는 해당 운송과 기록 탭으로 직접 연결되며 키보드 포커스도 옮긴다. 사라진 운송을 다른 운송으로 대체해 취소 버튼을 제공하지 않는다.
- 상신/보고 권한은 기존 산업 권한 창구로 연결한다. 화면 자체에 새로운 집행 권한을 만들지 않는다.

## 모델과 실행 경계

`regionalLogisticsPresentation.ts`는 현재 국가의 저장 기록에서 읽기 전용으로 계산한다. 새 저장 필드·출발 비용·생산 보너스·수송 명령은 만들지 않았다. 명령과 주간 결산은 기존 `regionalIndustry` 엔진을 사용한다.

화면의 선과 표식은 **결산 단계도**이며, 실제 도로·철도·차량 좌표를 뜻하지 않는다. 기존 엔진의 2회 유효 결산을 표현한다. 정지 중에도 움직이는 장식 차량이나 시간 기반 가상 이동은 없다. 이미 출발한 수송에는 새 출발 용량 부족을 잘못 적용하지 않는다.

도착 예고는 조건부 최소 결산 횟수다. 현재 차단 조건이 있거나 시점 근거가 불확실하면 예고를 숨긴다. 완료 기록은 현재 노선이 막혀도 과거의 실제 도착으로 유지한다. 미래 기록·다른 국가 영수증으로 현재 수량을 만들지 않는다. 격리된 저장은 0건으로 단정하지 않고 자료 확인 필요로 표시한다.

이번 구현은 전후 지역 집하 엔진에 연결되므로 전쟁 단계에 존재하지 않는 수송을 만들지 않는다. 일반 전시 보급, 실제 도로를 따르는 지도상의 이동, 복수 집하망은 이번 범위가 아니다.

## 검증

- 모델·관제판·화면 연결·기존 지역 산업·주간 결산·지휘부 통합: 7파일 99개 테스트 통과.
- TypeScript와 GitHub Pages용 빌드 통과. 기존 대형 번들 경고는 남아 있다.
- 기존 테스트 2개는 변경된 접근성 속성과 현재 용량 검증에 맞춰 보정했다. 보이는 기본 화면 검증은 유지하고, 중복 라벨 테스트는 실제로 용량이 있는 승인 노선을 사용한다.
- 브라우저는 로컬 격리 검증 페이지에서 실제 엔진을 실행했다. 12개 예약 → 다음 결산에 운송 → 경로 차단 결산에서 정지 → 복구 후 다음 결산에서 12개 비축 편입을 확인했다.
- `이 운송 기록 열기`가 같은 운송의 상세를 열고, 열람 권한에서 예약 취소가 비활성화됨을 확인했다. 기록 화면 진입 후 포커스는 `records` 영역이었다.
- 격리 화면에서 1920×1080, 2560×1440, 3840×2160 각각 문서 가로 넘침이 없었다. 전체 국가 캠페인 모든 패널의 재검증을 의미하지 않는다.
- 검증용 페이지의 HMR 중복 createRoot 경고를 발견해 dispose에서 unmount하도록 수정했다. 최종 새로고침 이후 새 브라우저 오류·경고는 없었다.
- 로컬 실행기/샌드박스 파일 도구 지연으로 작업 중 일부 명령이 실패했다. 단순 시도를 성공으로 기록하지 않았으며, 실제 파일 반영 후 위 테스트를 다시 실행했다.

재현: 기존 Vite 개발 서버에서 `/scripts/verify-regional-logistics.html`을 연다. 이 도구는 사용자 저장을 읽거나 쓰지 않고 실제 엔진 함수로 만든 격리 상태를 사용한다. 게임의 배포 엔트리에서는 불러오지 않는다.
