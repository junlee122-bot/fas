# 공간에서 운영하는 대체역사 — 게임 전체 확장 설계

## 목표

국가를 하나의 마을로 축소하지 않는다. **세계지도에서 전략을 세우고, 내가 관할하는 기관에서 실행하며, 사람과 실제 결과로 역사를 기억하는 게임**으로 연결한다.

기관 배치도는 새로운 메뉴 스킨이 아니라 `대상 선택 → 현재 업무와 막힌 조건 확인 → 내 권한으로 지시안 검토 → 시간 경과 → 실제 결과 확인 → 후속 판단`을 짧게 만드는 조작 계층이다. 세부 화면·세계지도·기존 결재는 유지한다.

## 참고와 적용 범위

Ludeon의 1.6 개발 안내는 용도별 색상 계획, 작업 시설에 적합한 방, 세계지도 대상 바로가기 등을 설명한다. 여기서는 **기능과 장소를 연결하고, 계획과 실행 상태를 구별하며, 필요한 대상으로 바로 이동하는 원칙**을 참고했다. 방 크기나 거리로 생산 보너스를 주는 시스템은 이번 게임에 구현된 것으로 취급하지 않는다. [공식 개발 안내](https://ludeon.com/blog/2025/06/announcing-odyssey-and-update-1-6/)

아래는 IRON DOMINION을 위한 설계 판단이다. 다른 게임의 실제 구현을 그대로 재현했다는 뜻이 아니다.

## 세 층의 플레이

| 층 | 플레이어의 질문 | 화면과 조작 |
| --- | --- | --- |
| 세계·지역 | 어디에 힘을 쓰고 누구와 관계를 맺을까? | 실제 지역·전선·통행권·점령·수송 경로를 세계지도에서 선택 |
| 기관·거점 | 그 선택을 누가 어떤 자원으로 수행하나? | 지휘부·생산실·연구실·창고·보건실의 현재 업무와 지시 |
| 사람·결과 | 누가 책임지고 무엇이 달라졌나? | 개인 결산·관계 현안·납품 증빙·전투 기록·주간 브리핑에서 후속 판단 |

층 사이의 이동은 가능하면 정확한 국가·기관·인물·명령·보고서 ID를 넘긴다. 찾던 대상이 사라지면 다른 대상으로 바꾸지 않고 재선택을 요청한다.

## 첫 구현: 연결된 기관 운영

이번 구현은 8개 기관과 3개 운영 흐름에 적용했다.

| 흐름 | 기관 연결 | 이번 구현의 실제 조작 |
| --- | --- | --- |
| 방위 역량 | 연구 → 생산 → 창고 → 작전 | 연구 시작·중지 검토, 군수·민수 배분 검토, 기존 물류·수송·지도 연결 |
| 민생·재정 | 재정 → 생산 → 창고 → 보건 | 현재 국고·경제·공급·보건 상태 파악, 공장 전환, 기존 정책 창구 연결 |
| 사람·조직 | 인사 → 재정 → 정무 → 지휘 | 참모 과로·계약·실제 결산 파악, 기존 개인 배치·면담·위임 및 상세 창구 연결 |

연결선은 판단 순서이며 실제 철도·운송·자동 보너스가 아니다. 연구의 진행 막대는 실제 누적 작업량이다. 공장 막대는 전체 역량 중 군수 배정 비중이며 생산 완료율이 아니다.

공간 상태는 `진행 중 / 점검 필요 / 검토 가능 / 대기·유지 / 기록 확인 필요`로 구분한다. 빈 연구 슬롯만으로 긴급 알림을 만들지 않고, 보급이 충분한 부대에 부족 경고를 만들지 않는다. 과거 결산은 현재 위기의 증거로 자동 승격하지 않는다.

## 게임성을 강화하는 후속 순서

### 1. 한 목표를 여러 기관에서 완결

예를 들어 ‘기갑부대 보급 정상화’를 고르면 생산 주문·부품 비축·실제 수송·도착·부대 보급을 하나의 추적 화면에서 연다. 플레이어가 무엇을 바꾸었는지와 여전히 다른 원인 때문에 막힌 부분을 함께 보여준다.

기존 납품 약속, 자동 출발 규칙, 실제 생산·도착 기록은 이미 있으므로 새 시스템으로 복제하지 않는다. **2026-09-24 후속 구현:** 지휘부의 이행 목표에서 생산라인·같은 품목의 현재 물류·실제 도착 영수증·동일 담당자로 연결하는 추적 화면을 추가했다. 정확한 국가·대상 ID로 이동하며 열람 자체는 명령·보상을 실행하지 않는다. [구현·검증 기록](delivery-goal-trace-2026-09-24.md)

특정 생산 묶음에서 특정 부대 수령까지의 귀속은 아직 구현하지 않았다. 현재 창고의 혼합 물량을 특정 참모의 공적으로 표시하지 않으며, 국가 가용 편입을 부대 수령으로 바꾸어 설명하지 않는다.

**추가 후속 구현:** 국가 가용 비축에서 특정 부대로 장비를 지급하는 별도 검토·승인과 수령 원장을 연결했다. 실제 비축 차감과 기초 보급 변화를 함께 기록하며, 원격 수송 경로나 특정 생산 묶음의 출처를 추정하지 않는다. [부대 지급 구현·검증](unit-equipment-issue-2026-09-24.md)

완료 기준: 생산 완료를 부대 수령으로 착각하지 않음, 운송 중 경로 변경이 옛 기록을 덮지 않음, 목표 달성에 같은 보상이 두 번 붙지 않음.

### 2. 참모가 기억되는 사건과 후속 행동

결산 카드에서 과로·계약·관계 악화의 당사자를 선택하고 면담·업무 완화·재배치로 이어간다. 이후 실제 결산을 나란히 비교한다. 부서의 모든 생산을 담당자 개인의 공적으로 계산하지 않는다.

관계·약속·자율성에 따른 장기 사건을 확장할 때는 성격별 선호, 플레이어의 약속, 실제 지원, 책임 공방을 연결한다. 사람을 교체하면 이전 사람의 관계나 공적을 상속하지 않는다.

### 3. 보직에 따라 다른 운영 현장

| 경력 | 주 무대 | 직접 결정의 범위 | 남의 권한이 필요한 행동 |
| --- | --- | --- | --- |
| 군사 | 작전실·군수 거점 | 지휘권 안의 부대·보급·참모 | 외교·상급 조달·국가 재정 상신 |
| 정치 | 내각·의회·행정 기관 | 보직과 헌법이 부여한 정책 | 연정·의회·지방·군의 협의 |
| 정보 | 정보 거점·연락망 | 소속·노출 상태에 맞는 작전 | 정치 승인·현지 협조·위장 자원 |
| 일반인 | 대학·상회·언론·시민 조직 | 개인의 시간·재산·인맥 | 국가 기관과의 계약·허가·협상 |

같은 국가 최고 지도자 화면에 직함만 바꾸지 않는다. 하급 보직의 재미는 제한을 없애는 것이 아니라 상신·설득·책임·경력 이동을 선택하는 데 있다. 이번 구현에서 일반인용 공간을 새로 만들지는 않았다.

### 4. 실제 거점 증설·피해·복구

건설로 넘어가기 전에 시설 ID, 지역 ID, 소유·사용권, 자원 예약, 공사 단계, 주간 실제 투입, 완공·손상·휴업·수리 상태를 영속 데이터로 만든다. 취소·점령·국가 이동·저장 복원도 함께 설계한다.

그다음 바닥·벽·문·장비·인물·상태 표식을 분리하여 실제 완공/손상 상태를 그린다. 현재의 국가 집계나 공급 부족을 개별 건물 파괴로 표현하지 않는다.

### 5. 공간과 세계사의 상호작용

전쟁·제재·봉쇄·질병·선거·체제 전환은 우선 기존 엔진의 실제 상태로 각 기관에 들어온다. 운영 현장에서 대응한 선택은 비용·시간·외교 관계·민간인 영향·조직 관계로 되돌아와야 한다.

새 사건을 늘릴 때에는 사건 수가 아니라 ‘평소 하던 선택이 달라지는가’를 기준으로 평가한다. 물자 우회, 연구 중지, 병상 확대, 연정 협상 등이 서로 다른 결과를 만들되 실패해도 경력과 국가의 다음 선택이 남아 있어야 한다.

## UI·미술·시간 진행 규칙

- 첫 화면에는 당장 관찰할 상태와 선택한 대상의 행동을 먼저 둔다. 긴 근거는 펼침 영역에 둔다.
- 계획, 지시 전달, 실제 처리, 확정 결과는 서로 다른 문구와 표식으로 표시한다.
- 선택·카메라 이동·화면 재생은 자원이나 진행도를 바꾸지 않는다.
- 바닥/가구 미술은 현재 레이어를 재사용한다. 장식 개수로 공장·병상·부대의 실제 수량을 암시하지 않는다.
- 인물 이동은 실제 목적지와 이동/업무 상태가 생긴 뒤 연결한다. 현재 초상은 조직 배치 표식이다.
- 주간 게임에서 의미 없는 실시간 채우기 애니메이션을 돌리지 않는다. 결산 뒤 달라진 상태를 안정적으로 보여준다.
- 긴 평시 진행은 기존 기간 진행·중단 조건과 연동하고, 새 승인 필요/위기/주요 결과에서 멈추도록 점검한다. 이번 묶음은 시간 엔진을 바꾸지 않았다.

## 보존해야 할 경계

현재 국가·경력·보직·권한·주차를 실행 직전에 확인한다. 방의 접근 권한은 모든 명령의 권한을 뜻하지 않는다. 작전실의 지도 열람과 육군 명령, 창고의 물자 수송과 병력 해상 수송은 서로 다른 권한이다.

승인 전에는 효과를 전망으로만 표시하고, 기존 기록에 없는 기여·성공률·완료 시점을 만들어내지 않는다. 데이터가 부족하면 불확실성을 보여주는 것이 계산된 듯 보이는 숫자를 붙이는 것보다 낫다.

## 성공을 판단하는 기준

신규 플레이어가 한 화면에서 ‘무엇을 할 수 있나’, ‘누가 담당하나’, ‘언제 무엇이 달라지나’를 설명할 수 있어야 한다. 주요 행동은 대상 선택과 검토·승인으로 도달하고, 승인 후에는 같은 대상의 실제 상태가 바뀌어야 한다. 실패나 보류는 다음 행동으로 이어지되 무한 경고와 반복 결재를 만들지 않아야 한다.

이 문서는 전체 확장의 방향이다. 역할별 새 거점, 실제 건설·이동, 모든 분야의 단일 목표 추적을 이미 구현한 것으로 표시하지 않는다.
