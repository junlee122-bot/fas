# IRON DOMINION — 상태가 보이는 액티브 월드 설계

조사일: 2026-09-08. 범위: 공식 자료 조사와 로컬 코드에 맞춘 설계. 이 문서는 앱 구현 완료 보고가 아니다. 게임 자산·화면·대사·음원을 복제하거나 내려받지 않았다.

## 결론

목표는 보고서를 없애는 것이 아니라, **누가 어디서 무엇을 하고 있으며 내가 내린 명령 때문에 무엇이 바뀌었는지 먼저 장면으로 읽고, 필요할 때 계산 근거를 펼치는 게임**으로 바꾸는 것이다.

권장 순서는 **소규모 현장 패널 → 지도 지역 생산현장 → 인물 회의장**이다. 새 창을 계속 추가하기보다 같은 선택 객체와 같은 명령을 세 수준으로 확장한다. 먼저 기존 전투·생산·인물 데이터의 표현을 개선하고, 지역별 생산 기반이 준비된 뒤 공간 자체를 의사결정 대상으로 만든다.

핵심 원칙: 장면은 계산 결과를 보여준다. 연기·트럭·회의 대사는 새로운 계산 엔진이 아니다. 화면이 활발하다는 이유로 생산량·전황·관계가 별도로 진행되면 안 된다.

확장 조사에서는 FM, CK3, HOI4, RimWorld, Frostpunk 2, XCOM 2, Total War, Stellaris까지 8개 사례를 추가했다. 아래 7~10장은 이를 기존 문명·삼국지·Victoria 3와 연결한다. **“다 들고오기”는 아이디어의 폭을 넓힌다는 뜻으로 해석하며, 모든 기능을 한 번에 추가하거나 타 게임의 코드·자산·대사를 복사한다는 뜻이 아니다.**

## 1. 공식 자료에서 확인한 설계 선례

아래 다섯 자료의 본문을 실제로 열어 확인했다. 문명 VII 두 자료는 현재 공식 아카이브이며, 제작사가 현행 게임과 차이가 있을 수 있다고 명시한다. 따라서 아래는 **공식적으로 설명했던 설계 선례**이지 2026년 최신 패치의 세부 규칙 보증이 아니다. Victoria 3 자료도 각각 개발 당시·1.2 개선 당시 설명으로 한정한다.

### 1.1 문명 VI에서 VII로: 성장과 선택이 도시의 모양이 된다

개발일지는 VI의 전문 지구와 VII의 유연한 도시 지구를 비교한다. VII 설명에는 건물 배치에 따른 지구 형성, 도시 타일당 두 건물 슬롯, 중심에서 인접 확장하는 도시 형태, 성장 인구의 타일 개선·전문가 배치가 포함된다. 마을은 지원 역할과 특화로 관리 부담을 줄이며, 배치 보너스 계산을 UI에 드러내는 것이 목표다. [공식 자료: Civilization VII Dev Diary #3 — Managing Your Empire](https://civilization.2k.com/civ-vii/archive/dev-diary/managing-your-empire/).

**우리 설계로 변환:** 건설·수리·배치의 결과가 시설 상태와 연결되게 한다. 철도 복구가 끝나면 지도에서 해당 연결이 복구되고, 보급 변화와 실제 결산 기록을 같은 객체에서 확인한다. 생산 거점은 전부 매주 손으로 돌리게 만들지 않고 중요한 병목만 개입한다.

**복제하지 않을 것:** 육각 타일 규칙·인접 보너스·도시 스킨을 그대로 가져오지 않는다. 현재 게임의 영토는 지점과 이웃 관계로 표현되므로, 타일 건설 배치가 실제 계산에 들어가지 않는 상태에서 문명식 타일을 그리면 허위 선택지가 된다. VI의 전체 규칙을 별도로 검증한 조사도 아니므로 VII 일지의 비교 설명 이상으로 VI 기능을 단정하지 않는다.

### 1.2 문명 VII 지휘관: 일괄 명령과 지속되는 전투 장면

전투 일지는 지휘관을 중심으로 부대 묶음 이동·전개, 지휘 범위 명령, 증원 요청과 경험·진급을 설명한다. 또 공격 후 원위치로 돌아오는 짧은 반복 대신 교전 모습이 지속되는 표현과 측면 공격의 연결을 설명한다. [공식 자료: Civilization VII Dev Diary #5 — Combat, 2024-12-18](https://civilization.2k.com/civ-vii/archive/dev-diary/combat/).

**우리 설계로 변환:** 군단/작전 그룹을 선택하면 지휘관, 투입 사단, 목표, 보급, 현재 작전 단계를 함께 표시한다. 동시 작전은 여러 전선에서 함께 표시하고, 공세 종료 전까지 교전 표식이 유지된다. 카메라 연출이나 반복 재생은 추가 피해를 계산하지 않는다.

**복제하지 않을 것:** 지휘관 중심 표현을 이유로 개별 부대 손실·편제를 없애지 않는다. 실제 이동 경로와 시간이 없는 상태에서 병력이 경로를 따라 도착했다고 보여주지 않는다. 범위 밖 지원·전력 0 편대 출격·시각적으로만 존재하는 증원을 허용하지 않는다.

### 1.3 삼국지8 리메이크: 평정·도시 생활·관계·전투가 한 인물의 연속 행동이다

공식 시스템은 분기마다 정책을 정하는 평정, 도시에서 맡은 임무 수행과 인물 교류, 야전·공성 전투의 순환을 설명한다. 관계도는 우호·대립을 드러내며 친밀한 인물의 협력이 내정·전투 성과에 영향을 준다. 이벤트는 조건과 결과를 제시한다. 전투 전 군의 배치·함정 선택, 전략 카드식 일기토와 설전도 소개한다. [공식 자료: ROMANCE OF THE THREE KINGDOMS 8 REMAKE — SYSTEM](https://www.koeitecmoamerica.com/rtk8-remake/system.html).

**우리 설계로 변환:** 참모를 메뉴 항목이 아니라 회의 참석자로 배치한다. 발언은 현재 업무·관계·압력·권한에 근거하고, 상신→검토→승인→현장 실행→사후 책임이 이어진다. 산업 장면의 담당 참모를 누르면 같은 사람의 회의 발언과 업무 기록이 열린다.

**복제하지 않을 것:** 20세기 국가 운영에 무장 일기토를 이식하지 않는다. 논쟁을 보여주는 방식은 참고할 수 있지만, 카드 미니게임 한 판으로 법률·예산·전쟁의 기존 조건을 무시하게 하지 않는다. 실존 인물의 초상·음성·대사·그림체를 게임 자료에서 가져오지 않는다. 사료에 없는 동기나 발언은 ‘게임 내 추정/구성’으로 구분한다.

### 1.4 Victoria 3: 공장 그림 뒤에는 사람과 투입·산출이 있다

개발 회고는 건물이 물품을 생산·소비하고, 인구가 고용되어 임금을 받아 생활하며, 산업 변화가 정치 집단의 힘에도 영향을 주는 연결을 설명한다. 공공서비스 역시 법을 제정하면 저절로 생기는 효과가 아니라 행정 역량과 비용을 필요로 한다는 설계 고민이 제시된다. [공식 자료: Victoria 3 Dev Diary #57 — The Journey So Far](https://www.paradoxinteractive.com/games/victoria-3/news/dev-diary-57-the-journey-so-far).

**우리 설계로 변환:** 생산현장은 현재 가동·할당·효율·실제 산출을 보여준다. 이후 지역 경제를 도입하면 노동·원료·수송 병목이 시설 상태를 결정하게 한다. 법률/예산은 승인 즉시 완성된 병원 풍경이 아니라 집행 중, 인력 부족, 운영 중 등으로 표현한다.

**복제하지 않을 것:** 인구·임금·지역 원료 재고가 아직 모델에 없는데 화면에서 실제처럼 만들어내지 않는다. Victoria 3 전체 경제를 한 번에 복제하거나, 모든 보조 지표를 매주 플레이어가 조작하게 하지 않는다.

### 1.5 Victoria 3 UX: 지도 위 행동에 판단 자료와 원인 설명을 붙인다

1.2 UX 일지는 건물 확장 지도 목록에 기반시설·가용 노동·자격 정보를 붙이고, 건물 상세로 바로 이동하는 흐름을 설명한다. 시장 접근성의 원인, 전투 계산과 투입 병력, 알림 중요도 구분도 다룬다. [공식 자료: Victoria 3 Dev Diary #74 — UX Improvements, 2023-02-08](https://www.paradoxinteractive.com/games/victoria-3/news/dev-diary-74-ux-improvements).

**우리 설계로 변환:** 현장 선택→상황·제약 확인→행동→결산 비교를 같은 흐름에 둔다. 알림 개수보다 해결할 수 있는 원인을 먼저 보여준다. ‘부족’이라는 빨간 아이콘만 두지 않고 부족량, 관련 정책/시설, 직접 집행 또는 상신 버튼을 붙인다.

## 2. 현재 코드가 허용하는 것과 아직 허용하지 않는 것

아래는 조사 시점 로컬 작업 트리를 읽은 결과다. 동시에 진행 중인 변경 때문에 줄 번호는 이후 이동할 수 있다.

| 현재 근거 | 바로 표현할 수 있는 사실 | 추가 모델 없이 표현하면 안 되는 사실 |
| --- | --- | --- |
| `src/types.ts`의 `Territory`, `src/mapRegions.ts`, `src/historicalMaps.ts` | 영토 ID·소유·통제·지형·보급·이웃과 지도 선택 | 임의 도시 구획의 점유, 존재하지 않는 도로별 운송량 |
| `src/types.ts`의 `ProductionLine`, `src/engine.ts`의 `calculateProductionGains` | 생산라인 할당·효율·장비와 주간 산출 | 특정 도시의 공장 위치·고용 인원·시간당 산출. 현재 생산라인에는 `territoryId`가 없다 |
| `src/jointOperations.ts`, `src/landOperations.ts` | 실제 배속·남은 전력·단계·진척·목표·승패·지원 효과 | 전력 규모와 무관한 출격 쇼, 계산되지 않은 실제 이동 거리·실시간 피해 |
| `src/staffNarrative.ts`의 `bonds`, `activeStorylines`, `history` | 참모 간 친화·불만·현안·기한·결정과 검증 | 모든 역사 인물이 현재 같은 회의실에 존재한다는 가정 |
| `src/roleCommand.ts`, `src/CouncilEventModal.tsx` | 보직 권한·상신 상태·의제 선택·실제 행동 증거 | 화면 입장만으로 업무 성과 획득, 관찰자도 곧바로 정책 집행 |
| `src/nationManagement.ts`의 `NationManagementState` | 국가 단위 고용·인프라·교육·주거·불안 지표 | 국가 평균을 임의 지역의 정확한 값이라고 표기 |
| `src/types.ts`의 `WarEventTrace` | 원인·선택·요인·효과·예측/결산 비교와 확실성 | 아직 없는 개체별 위치·기계적 변화량을 자유문장에서 확정적으로 추출 |

특히 **국가 생산라인을 임의의 수도에 꽂고 해당 도시가 생산했다고 표시하면 안 된다.** 첫 구현은 ‘국가 산업 현황’으로 명시한다. 실제 지역 귀속 데이터가 없는 항목은 ‘지역 미배정’으로 남겨 둔다.

## 3. 공통 화면 구조: 장면, 조작, 근거를 한 객체에 묶기

다음은 제안하는 신규 구조이며 기존 API가 이미 존재한다는 뜻이 아니다.

```text
실제 저장 상태 / 주간 결산 / 명령 승인
                ↓
       읽기 전용 장면 투영기
                ↓
   현장 패널 ─ 지도 지역 ─ 인물 회의장
                ↓ 클릭
    기존 권한 검사 → 기존 명령 처리 → 다음 결산
```

장면 객체마다 `sourceKind`, `sourceId`, `snapshotWeek`, `status`, `label`, `evidenceId`, `allowedActions`를 가진다. 이것은 제안 스키마다. `sourceId`가 실재하지 않는 장면 객체는 생성하지 않는다. 적 정보는 확인된 범위만 투영하고 미확인 배치와 확률은 구분한다.

세 화면은 동일한 선택 문맥을 공유한다. 예를 들어 `territoryId`로 선택한 전선에서 사단→지휘관→지원 작전→결산 기록으로 이동할 때 다른 인물이나 다른 전구로 바뀌지 않아야 한다.

### 표현 규칙

- 공장 가동 표시는 할당과 효율에 대응하는 상태 표현이다. 실제 계산에 연료 차단 로직이 없다면 연료가 적다는 이유만으로 가동 중단 연출을 만들지 않는다.
- 차후 운송선 표현은 실제 출발·도착·물량·기간이 기록된 운송만 사용한다. 아직 경로 계산이 없으면 점선 ‘관련 보급축’으로 표시하고 실제 운송으로 부르지 않는다.
- 교전 장면은 승인된 활성 명령에만 표시한다. 이번 주의 사상자는 결산 기록을 한 번 재생하고, 루프 애니메이션이 피해를 추가하지 않는다.
- 도시 확장·수리 완료·연구 완성은 실제 완료 이벤트 후에만 구조물 상태를 바꾼다. 새 정책 채택은 운영 중과 구분하여 ‘집행 준비’로 표시한다.
- 회의 발언은 현재의 참가자·현안·권한·관계에 연결한다. 다른 국가/시대의 인물은 참여 조건이 검증되지 않으면 배치하지 않는다.
- 화면의 사람·차량 아이콘은 표본 표현임을 밝힌다. 아이콘 하나를 실제 사단·차량 한 대와 혼동하게 하지 않는다.
- 현재 상태, 예상 다음 주, 이번 주 확정 결과를 서로 다른 문구로 구분한다. 예측 장면은 저장 상태를 수정하지 않는다.
- 일시정지하면 세계 시간은 진행되지 않는다. 정보 강조·호버 같은 UI 반응은 허용하되 운송·생산·전투 진행을 암시하는 루프는 정지하거나 정적 표시로 바꾼다.
- 움직임 줄이기 설정에서는 같은 정보를 정적 상태·짧은 변화 강조·텍스트로 제공한다. 중요한 차이는 색상이나 소리 하나에만 의존하지 않는다.

## 4. 구체적 3단계 로드맵

### 1단계 — 이번 묶음: 작은 현장 패널로 실제 행동을 앞에 놓기

**결과물:** 상황실 또는 군사/산업 탭 안에 접을 수 있는 단일 현장 영역. 독립적인 새 세계지도나 새로운 경제 엔진을 만들지 않는다.

첫 화면은 3개 현장 중 실제 데이터가 있는 것을 보여준다.

1. **작전 현장:** 선택한 목표와 실제 투입 사단/함대/항공대, 진행 단계, 남은 전력, 최근 결산. 지속 교전 표식과 짧은 확정 변화 재생을 사용한다.
2. **국가 산업 현장:** 생산라인 작업대/격납고의 개념도. 할당·효율·예상 주간 산출과 최근 확정 산출을 표시한다. 지역 데이터가 없으므로 특정 도시명이나 지역 고용 수치는 붙이지 않는다.
3. **참모 현장:** 현재 재직 참모 중 실제 현안 담당자와 기한, 관계 또는 업무 부담을 간단히 표시한다. 없는 현안을 연출용으로 생성하지 않는다.

**조작:** 장면 클릭은 기존 명령으로 연결한다. 권한이 있으면 배치/할당/정비/결정, 없으면 상신/열람을 제공한다. ‘현장 선택 → 행동 1개 → 즉시 비용 확인 → 주간 결산 확인’을 일관되게 만든다. 버튼을 눌러야만 모션이 달라지는 장식용 기능은 넣지 않는다.

**이번 단계 제외:** 도시별 실제 공장 배치, 이동 차량의 물량 시뮬레이션, 3D 카메라, 일기토/설전 카드 게임, 여러 참모의 실시간 자율 대화.

**완료 조건:**

- 같은 저장 상태를 표시하는 기존 패널과 현장 패널의 수치·권한·가용 행동이 모두 일치한다.
- 최소 한 군사 행동과 한 생산 행동을 현장에서 기존 명령 처리로 실행할 수 있다. 권한 없는 보직은 같은 행동을 집행하지 못한다.
- 전력 0, 명령 없음, 자원 부족, 민간 출발, 전후 단계에서 허위 가동/교전이 없다.
- 화면 열기·닫기·반복 렌더링은 자원·업무 완료·작전 진행을 변경하지 않는다.
- 결정 전/후 비교가 `sourceId`와 결산 기록으로 추적된다. 장면 표시 여부가 고정 시드 결과를 바꾸지 않는다.

### 2단계 — 지도 지역 생산현장: 위치에 실제 비용과 가치 부여

**선행조건:** 생산 거점의 지역 귀속 모델부터 만든다. 제안 필드는 `siteId`, `territoryId`, `ownerId`, `productionLineId`, `capacity`, `condition`, `constructionState`, `allocation`이며 실제 노동·원료·운송 체계가 도입된 경우에만 관련 수치를 추가한다.

구세이브의 국가 생산력을 지도에 임의 균등 배분하지 않는다. 확인 가능한 시나리오 배치 또는 사용자 이전 절차가 마련되기 전까지 `unlocatedNationalCapacity` 같은 명시적 미배정 계정에 보존한다. 이것도 제안 필드다. 지역화 전후 생산 총합·할당·재고가 보존되어야 한다.

**결과물:** 기존 지역 지도 위 시설 마커와 선택 지역의 2D/2.5D 현장도. 신규 지역 모델로 확인된 공장·철도·항만만 표시한다. 장면을 클릭하면 가동 전환·투자·수리·이전의 실제 비용과 기간을 미리 보고 승인한다.

**플레이 루프 예시:** 항만 통제 상실 → 실제 수송 용량 하락 → 연결 공장의 투입 또는 출하 차질 → 손실 원인 강조 → 수리/대체 경로/생산 전환 승인 → 다음 결산에서 회복 확인. 이 연결이 엔진에 없다면 우선 ‘계획 단계’ 설명만 두고 완성된 기능처럼 연출하지 않는다.

**관리 부담 제한:** 지역 특화와 담당자 위임을 지원한다. 중요한 지역은 자세히, 안정된 지역은 요약한다. 각 지역의 공장 모두에 매주 클릭을 요구하지 않는다.

**완료 조건:**

- 시설→영토→주간 산출의 귀속이 검증되고 국가 총계와 지역 합계의 중복 계산이 없다.
- 영토 상실/수리/이전/봉쇄가 실제 생산·보급에 적용되고 장면과 결산이 동일한 원인을 제시한다.
- 기존 원도 좌표와 태평양 부도 투영을 존중한다. 역사 배경지도 위에 현대 도로·공장을 근거 없이 그리지 않는다.
- 건설 계획/실제 완공/확인되지 않은 사료 배치가 시각적으로 구분된다.
- 지역을 반복해서 열거나 줌을 변경해도 계산이 재실행되지 않는다.

### 3단계 — 인물 회의장: 관계와 권한을 직접 다루는 결정 공간

**결과물:** 현재 재직 인물과 실제 의제가 있는 회의 테이블. 안건의 관련 현장도와 예산/권한 검증을 같은 화면에 둔다. 빈 자리, 위임 참석, 교체된 담당자는 실제 인사 상태를 반영한다.

**플레이 루프:** 안건 제기 → 현장 근거 제시 → 이해관계자 반응 → 상신/수정/승인/보류 → 비용 집행 → 현장 변화 → 약속 이행과 사후 책임. `staffNarrative`의 관계·기한·결정 기록과 `roleCommand`의 승인 상태를 재사용하고, UI 전용 호감도나 별도 승인 점수를 만들지 않는다.

**회의 행동:** 근거 제시, 담당자 변경, 지원 조건 조정, 기한 재협상, 공식 승인 같은 제한된 선택을 제공한다. 사용자가 자유문장을 넣더라도 기존 엔진에 없는 효과를 임의 생성하지 않는다. 전투는 장군의 일기토로 대신하지 않고 작전 검토·책임·증원 협상으로 연결한다.

**인물 표현:** 발언 강조, 시선, 문서 제출, 의견 연결선처럼 저비용 연출부터 시작한다. 표정은 명시된 상태 범주에만 연결한다. 가공 대사를 역사적 직접 인용처럼 제시하지 않는다. 인물 수가 많을 때는 안건 관련 인물만 전면에 둔다.

**완료 조건:**

- 안건 참가자에게 재직·시대·소속·권한 근거가 있고, 사료 인물 소개와 실제 참석이 혼동되지 않는다.
- 신뢰/갈등 변화가 실제 선택 결과로 남고 다음 검증 시점에 다시 확인된다.
- 동일 안건은 한 번만 집행되고 재접속·재생으로 비용/보상/관계가 중복 변경되지 않는다.
- 거절·보류·월권의 결과가 실제 권한/관계/현장 상태에 연결된다.
- 회의장과 기존 목록 UI가 같은 명령을 사용한다. 연출을 건너뛰어도 같은 결과를 얻는다.

## 5. 적용하면 안 되는 접근

| 유혹 | 위험 | 대신 할 일 |
| --- | --- | --- |
| 모든 지역에 멋진 공장과 왕래 차량 배치 | 존재하지 않는 지역 생산·물류를 실제인 것처럼 보이게 함 | 지역 귀속이 없는 생산은 국가 개념도에 두기 |
| 연기를 많이 내면 생산이 높은 것으로 표현 | 실제 효율·투입 부족과 모순되거나 오염을 보상처럼 읽게 함 | 가동/중단/정비 상태와 수치를 우선하고 오염은 별도 근거가 있을 때만 표현 |
| 모든 전선에서 군인이 계속 싸우게 만들기 | 명령이 없는 전선까지 활성 전투로 오인 | 활성 작전·최신 교전 기록에만 전투 표시 |

| 다른 게임의 타일·카드·건물·인물 자산 복제 | 제품 정체성 혼합, 라이선스 및 맥락 문제 | 원리만 참고하고 자체 제작한 추상 도형·아이콘·텍스트 사용 |

## 6. 이번 구현 묶음의 권장 범위

이번에는 **1단계의 작은 패널과 읽기 전용 투영기를 완성하는 것**이 적절하다. 실제 명령 하나를 현장에서 실행하고, 기존 결산과 동일한 결과를 확인하는 세로 흐름을 먼저 확보한다. 지역 생산과 회의장은 화면 목업보다 데이터 계약·권한·결산 불변 조건을 먼저 확정한다.

성공 기준은 애니메이션 개수가 아니다. 플레이어가 한 장면에서 “이 부대/공장이 왜 멈췄는지, 내가 무엇을 할 수 있는지, 행동 후 무엇이 달라졌는지”를 읽을 수 있는지가 기준이다.

## 7. 비교 범위 확장: 8개 게임에서 하나씩만 가져올 원리

다음 링크는 2026-09-08에 공식 본문을 실제로 열어 확인했다. 게임별 **확인한 기능**과 **우리 게임을 위한 제안**을 구분한다. 개발일지는 발행 당시의 설명이며 현행 패치 수치·DLC 포함 범위를 모두 검증한 자료가 아니다. Steam 자료는 이용자 리뷰나 언론 피드가 아니라 개발사 공식 공지 본문만 사용했다.

우선순위는 출시 일정을 뜻하지 않는다. **P0 = 이번 현장 패널의 진실성에 필요한 기반, P1 = 기반 다음에 한 흐름씩 검증, P2 = 새 시뮬레이션 데이터가 있어야 도입**이다. 한 게임 전체가 아니라 아래에 좁힌 메커닉만 평가한다.

### 7.1 Football Manager 2024 — 조건과 기한이 있는 업무 약속

**확인한 기능:** 개인 목표를 협의하고 진행을 추적하며, 목표 달성에 연결한 출전·계약 약속을 지켜야 한다. 실패 반응은 부상 등 맥락을 고려한다. [공식: Individual Player Targets and Interaction Logic, 2023-09-22](https://www.footballmanager.com/features/individual-player-targets-and-interaction-logic). 현재 사이트 표제는 FM26이지만 해당 본문은 명시적으로 FM24를 설명한다.

- **변환:** 참모에게 “생산을 늘려라”가 아니라 실제 지표와 기한이 있는 업무를 맡긴다. 현장 패널의 담당자 옆에서 목표·진척·지원 약속을 보고, 완료 후 같은 사람이 약속 이행을 확인한다. 회의는 할당 화면의 다른 표현이어야 한다.
- **필요 데이터:** 기존 `roleCommand` 업무·행동 증거와 `staffNarrative`의 기한/검증 기록을 재사용한다. 추가가 필요하면 `assigneeId`, `metricKey`, `baseline`, `target`, `dueWeek`, `promisedSupport`, `evidenceIds`, `reviewStatus`를 업무 소유 모델에 둔다. 예산 미승인·담당자 교체·강제 동원 같은 면책/재협상 사유도 기록한다.
- **하지 않을 것:** 확인 불가능한 “최선을 다함”을 성공 조건으로 쓰거나, 목표를 보러 간 횟수로 평가하지 않는다. 통제 밖 사건을 전부 담당자 탓으로 돌리지 않는다. 선수 계약·이적시장·축구 능력치를 국가 운영에 이식하지 않는다.
- **우선순위:** **P1.** 기존 업무 한 종류의 목표→증거→후속 대화부터. 새 인사 경영 게임 전체는 제외.

### 7.2 Crusader Kings III — 관계의 이유가 되는 개인 기억

**확인한 기능:** Friends & Foes는 인물의 과거 경험을 회상하고, 굴욕이나 오래된 원한이 현재 관계와 후속 이야기에 연결되는 경험을 설명한다. [공식: Crusader Kings III — Friends & Foes](https://www.paradoxinteractive.com/games/crusader-kings-iii/add-ons/crusader-kings-iii-friends-and-foes).

- **변환:** “신뢰 42” 대신 “이전 지원 요청을 거절했고 그 작전이 실패했다”처럼 실제 기록에서 나온 이유를 보여준다. 이후 같은 인물에게 다시 맡길 때 관련 기억 하나가 의견의 근거로 나타난다. 인물 카드는 기억을 열람하는 곳이지 관계 보너스를 생성하는 곳이 아니다.
- **필요 데이터:** `staffNarrative`의 `history`, `bonds`, 실제 사건 증거를 우선 사용한다. 기억 항목에 `actorIds`, `sourceEventId`, `occurredWeek`, `knownToIds`, `interpretation`, `expiryOrReviewWeek`가 필요할 수 있다. **사건 사실과 각 인물의 해석은 분리**하고, 관계 수치는 기존 계산 결과를 사용한다.
- **하지 않을 것:** 중세 가문 복수·혼인 정치·암살 체계를 그대로 가져오지 않는다. 실제로 참석하지 않은 사람이 비밀 회의를 기억하게 하지 않는다. 없는 과거를 생성 대사로 메우거나 모든 역사적 인물의 사생활을 단정하지 않는다.
- **우선순위:** **P1.** 기존 증거 3종(지원 약속, 인사 변경, 작전 결과)만 연결. UI 전용 두 번째 기억/호감도 엔진은 금지.

### 7.3 Hearts of Iron IV — 보급이 공간과 전력 사이의 제약이다

**확인한 기능:** 2021년 보급 일지는 철도·열차가 보급 허브를 연결하고, 트럭이 말단 수송에 기여하며, 열차 부족과 군수 타격이 수송 능력을 제약한다고 설명한다. 열차 움직임은 개별 조종이 아니라 보급 흐름에 따르는 시뮬레이션이다. [공식 개발사 Steam 공지: Trains and Supply, 2021-09-01](https://store.steampowered.com/news/posts/?appids=394360&enddate=1631106048&feed=steam_community_announcements).

- **변환:** 지금은 실제 전선 보급 수치와 전투 영향, 지원 작전의 대상과 결과를 같은 장면에서 연결한다. 지역 물류가 생긴 뒤에만 “이 노드가 끊겨 이 전선의 보급이 감소했다”는 경로를 표현한다. 지도에서 병목을 선택하면 수리·수송 우선순위·공세 축소 중 **실제로 지원되는 행동**을 제시한다.
- **필요 데이터:** 기존 영토·전구·작전·보급 필드는 바로 사용 가능하다. 진짜 수송망에는 `nodeId`, `edgeId`, `capacity`, `condition`, `controlledBy`, `routeDemand`, `deliveredSupply`, `allocationRule`, `repairOrderId`가 필요하다. 수송기/차량 재고까지 도입한다면 생산·손실·정비와 같은 장부를 써야 한다.
- **하지 않을 것:** 현재 영토의 이웃 관계를 검증된 철도 노선으로 둔갑시키지 않는다. 예쁜 열차를 보이기 위해 가짜 배달량을 만들지 않는다. 장거리 수송 모델 없이 HOI4 허브 반경·장비 수치·전차 설계기를 통째로 넣지 않는다.
- **우선순위:** **P0 = 기존 보급/지원 근거 표시, P2 = 지역 물류망.** 노선 추가 전에 지역 생산 귀속과 수송 배분 보존을 검증한다.

### 7.4 RimWorld — 현재 상황을 읽어 사건의 리듬을 편성한다

**확인한 기능:** 공식 소개는 사건을 단순 무작위 나열이 아니라 AI Storyteller가 조율하는 이야기로 설명하며, 서로 다른 이야기 진행 성향을 제시한다. [공식: RimWorld — Sci-Fi Colony Sim](https://rimworldgame.com/).

- **변환:** 이미 존재하는 부족·갈등·기한·외부 압력을 묶어 다음에 플레이어가 다룰 중요한 현안을 고른다. 매주 재난을 더 생성하기보다 같은 문제의 경고→악화→개입→회복을 보여준다. 안정기에는 회복과 준비도 드러내어 위기의 대비가 의미 있게 한다.
- **필요 데이터:** 실제 사건 후보의 `causeIds`, `severity`, `scopeIds`, `lastShownWeek`, `cooldown`, `repeatKey`, `resolutionState`, 노출용 긴장 예산. 새 확률 사건이 필요하면 저장된 시드·추첨 결과·사건별 전제조건을 둔다. **알림 편성기와 세계 상태를 바꾸는 사건 해결기는 분리**한다.
- **하지 않을 것:** 플레이어가 잘한다는 이유만으로 원인 없는 재난을 추가하지 않는다. 화면에 긴장이 부족하다고 자원·사람을 몰래 소모하지 않는다. 식민지 주민의 신체·욕구 시뮬레이션 전체나 기존 스토리텔러 이름·성격을 복제하지 않는다.
- **우선순위:** **P1.** 새 사건을 늘리기 전에 기존 사건의 중복 제거와 긴급도/후속 연결부터. 실제 실패·필수 선택은 편집상 휴식 때문에 숨기지 않는다.

### 7.5 Frostpunk 2 — 같은 정책을 다르게 평가하는 사회 집단

**확인한 기능:** 2024년 공식 소개는 일자리·식량·주거·건강 등 충돌하는 요구, 급진 세력의 긴장, 법안에 대한 대표들의 표결을 설명한다. [공식: Frostpunk 2 — First Gameplay Trailer, 2024-01-16](https://11bitstudios.com/frostpunk-2-on-the-first-gameplay-trailer/). 출시 전 소개이며 현재 세부 협상 규칙이나 정확한 표 수는 이 자료로 단정하지 않는다.

- **변환:** 산업 확대 안건에 생산 담당자는 찬성하고 복지 담당자는 주거 부담을 지적하는 식으로, **같은 실제 비용과 결과를 다른 이해관계로 평가**하게 한다. 현재 단계에서는 재직 참모의 자문으로 표현한다. 이후 실제 대표 집단 모델이 있을 때만 의석과 표결로 확대한다.
- **필요 데이터:** 기존 국가 고용·주거·불안·정당성 지표와 정책 비용을 공통 근거로 사용한다. 실제 표결에는 `groupId`, `representedPopulationOrMandate`, `seats`, `policyPreference`, `supportConditions`, `commitments`, `voteRecord` 및 국가별 의결 권한 규칙이 필요하다. 국가 평균을 지역 노동자의 정확한 요구라고 표시하지 않는다.
- **하지 않을 것:** 모든 국가·시대에 동일 의회/정당 모델을 강제하지 않는다. 군부 자문회의를 민선 의회인 것처럼 연출하지 않는다. 무슨 정책이든 같은 “찬성 점수”만 채우게 만들거나 가짜 군중으로 결과를 정당화하지 않는다. 원작 극한 기후·발전기 중심 경제는 제외.
- **우선순위:** **P2.** 3단계 회의장의 사회적 확장. 이번에는 근거 있는 이견 표시만; 실재 의석 없이 표결 UI를 먼저 만들지 않는다.

### 7.6 XCOM 2: War of the Chosen — 사람을 보내면 그 자리가 빈다

**확인한 기능:** 공식 안내는 군인·과학자·기술자를 비밀 임무에 파견하고 성공 시 자원·세력 관계상의 성과를 얻는 기능을 설명한다. [공식: 2K Support — XCOM 2: War of the Chosen, What's new](https://support.2k.com/hc/en-us/articles/115011824308--XCOM-2-War-of-the-Chosen-What-s-new).

- **변환:** 외교단·군수 조사단·정보 임무를 맡길 때 “이 담당자가 지금 본부에 없어 다른 업무에 투입할 수 없다”는 비용을 보여준다. 이미 진행 중인 전략 임무를 현장에서 표시하는 것부터 시작하고, 실제 인력 배속 모델이 생기면 파견/귀환을 연결한다.
- **필요 데이터:** 기존 전략 작전의 기간·비용·성과를 재사용한다. 새 배속에는 `assignmentId`, `staffIds`, `startWeek`, `endWeek`, `status`, `reservedCapacity`, `returnOutcome`, `resolutionId`가 필요하다. 사망·퇴임·중도 취소·체제 전환 시 처리와 중복 배속 금지 규칙을 먼저 정한다.
- **하지 않을 것:** 현장에도 있고 해외에도 있는 이중 인력을 허용하지 않는다. 열람 시 임무가 완료되거나 같은 귀환 보상이 다시 지급되게 하지 않는다. XCOM의 소규모 사격 전술, 능력 카드, 외계 세력, 캐릭터·포스터 자산은 가져오지 않는다.
- **우선순위:** **P1.** 기존 전략 임무 한 종류를 배속·공석·귀환까지 닫힌 흐름으로 검증. 여러 새 임무 체계의 동시 추가는 제외.

### 7.7 Total War: ROME II — 전략지도의 위치가 교전에 이어진다

**확인한 기능:** 공식 매뉴얼은 목적지 도착 후 교전 선택, 지원 가능한 군대 사이의 연결선, 캠페인 지형과 전장 지형의 대응, 전투 결과를 남기는 지도 표식을 설명한다. [공식: Total War: ROME II Encyclopaedia — Attacking the Enemy](https://r2enc.totalwar.com/en/manual/single-player/0016_enc_page_campaign_play_military_attack/).

- **변환:** 우리 게임에서는 지도 목표→실제 배속/유효 지원→결산 장면→영토와 부대 상태 갱신을 하나로 잇는다. 교전 장면을 상세화하더라도 기존 전투 결과의 설명/재생부터 한다. 지원 연결선은 같은 주에 실제 적용된 지원만 보여준다.
- **필요 데이터:** `orderId`, `battleId`, `targetTerritoryId`, `participantIds`, `supportAllocation`, `beforeSnapshot`, `losses`, `afterSnapshot`, `resolvedWeek`의 참조가 필요하다. 현재 작전 결과에서 얻지 못하는 항목은 모델을 먼저 보강하고, 연출용으로 추정해 확정 표시하지 않는다.
- **하지 않을 것:** 국가 경영 게임 안에 별도의 실시간 3D 전술 게임을 즉시 만든다는 약속을 하지 않는다. 재생 중 피해를 다시 계산하거나 전투를 다시 보았다는 이유로 결과를 바꾸지 않는다. 지원 불가 부대를 연결선으로 연결하거나 고대 전투 병종을 현대전에 이식하지 않는다.
- **우선순위:** **P0.** 유효 배속·지원·실제 손실을 현장 패널과 지도에 일치시킨다. 직접 조종 전술 모드는 이번 로드맵 밖이다.

### 7.8 Stellaris — 팝업 하나가 아니라 진행 중인 현안

**확인한 기능:** Situations 개발일지는 대상이 있는 현안, 주기별 진행/후퇴, 단계 변화, 지속 비용을 지닌 대응 방침과 종결을 설명한다. 단계와 변화 요인을 보여주어 사건 사이의 연결을 읽게 하는 설계다. [공식 개발사 Steam 공지: Dev Diary #245 — We have a Situation, 2022-03-10](https://store.steampowered.com/news/posts/?appids=281990&enddate=1649934144&feed=steam_community_announcements). 당시 목업과 미확정 수치는 구현 명세로 가져오지 않는다.

- **변환:** “주택 부족 -5” 팝업을 매번 새 사건처럼 띄우기보다 하나의 주택 현안을 유지한다. 악화 원인·담당자·현재 대응·예상 다음 단계와 확정 결과를 보여준다. 같은 패턴을 전후 재건·산업 전환에도 쓰되 기존 국가 의제/계획을 감싸는 표현으로 시작한다.
- **필요 데이터:** `issueId`, `sourceOwner`, `scopeIds`, `stage`, `driverEvidenceIds`, `activeApproach`, `recurringCost`, `thresholds`, `completionRule`, `resolvedWeek`. 진행도를 이미 가진 업무는 그 값을 그대로 참조한다. 없는 진행도를 UI가 임의 생성하지 않는다.
- **하지 않을 것:** 모든 경제 문제에 별도 진행 막대와 자체 부작용을 만들어 기존 불안/물가 계산에 이중 벌점을 붙이지 않는다. 연도만 도달하면 위기가 자동 완료되거나 강제 발동되게 하지 않는다. 우주 종족·승천·은하 위기·원작 이벤트 문구는 제외.
- **우선순위:** **P1 = 기존 현안의 일관된 단계 표현, P2 = 시대 전환 계약.** 먼저 기존 장기 계획 한 건과 사건 두 건의 인과 연결을 검증한다.

## 8. 6개 대분류로 응집: 여러 게임의 메뉴가 아니라 한 국가의 생활

다음은 조사 결과를 바탕으로 한 **우리 제품의 설계 판단**이다. 어느 비교 게임이 이 구조 전체를 구현했다는 주장이 아니다. 여섯 분류는 여섯 새 탭이 아니라 같은 선택 객체의 다른 측면이다.

| 대분류 | 묶는 선례 | 플레이어가 직접 하는 일 | 한 가지 상태 근거와 첫 경계 |
| --- | --- | --- | --- |
| **업무 현장** | FM의 약속, 삼국지의 도시 업무, XCOM의 파견 | 담당자 선택→실제 업무/자원 배정→현장 진척 확인 | 기존 업무·배속·생산라인을 사용. 새 현장 그림 때문에 두 번째 업무 큐를 만들지 않음 |
| **사람과 기억** | CK3의 과거 경험, 삼국지의 관계, FM의 사후 약속 | 반대 이유 확인→지원 조건/기한 조정→책임과 신뢰 확인 | `staffNarrative` 사건·관계가 원본. 인물별 지식 범위·현재 재직을 검증 |
| **경제와 영토** | 문명의 눈에 보이는 성장, Victoria 3의 투입/고용, HOI4의 수송 | 병목 위치 선택→투자/배분/복구→산출과 접근성 확인 | 국가 생산을 먼저 정직하게 표시. 지역 거점·물류 모델 후에만 실제 지역 효과 제공 |
| **전쟁** | HOI4의 군수, 문명의 지휘관, Total War의 지도-교전 연결 | 목표·배속·지원 판단→공세/중단→전력·통제 변화 확인 | 실제 명령·유효 지원·결산 기록. 실시간 연출이 전투 엔진을 대신하지 않음 |
| **다이나믹 사건** | RimWorld의 사건 리듬, Stellaris의 현안, Frostpunk의 이해 충돌 | 원인이 누적된 현안 발견→대응 선택→비용/후속 결과 관리 | 기존 원인·시드·사건 ID. 사건 수 증가보다 중복 방지와 인과 연속성 우선 |
| **시대 전환** | Victoria 3의 제도 집행, Stellaris의 단계형 현안, CK3의 과거 연속성 | 전환 준비→미해결 문제와 자산 인수→새 역할/정책 선택 | `nationManagement` 전환 준비도와 기존 장기 계획을 기반으로 함. 배경만 바꾸거나 국가·사람·부채를 초기화하지 않음 |

### 시대 전환을 특별히 다루는 이유

시대 전환은 새 콘텐츠 메뉴를 열어주는 보상보다 **이전 선택을 새 조건에서 다시 책임지는 과정**이어야 한다. 전쟁에서 늘린 군수 생산, 떠맡은 부채, 살아남은 참모, 지역 피해와 약속이 전후에도 설명 가능한 형태로 남아야 한다. 장기 국가 운영에서는 제도 노후화·세대 변화 같은 이미 존재하는 압력과 장기 계획을 활용하되, 달력 숫자만으로 시대별 재난을 반복하지 않는다.

필요한 신규 계약은 `transitionId`, `fromPhase`, `toPhase`, `readinessEvidence`, `carryOverLedger`, `unresolvedCommitments`, `actorSuccession`, `effectiveWeek`, `appliedOnce`다. 이는 제안이지 현재 구현 필드 목록이 아니다. 기술·기관·정책의 등장 가능 시기와 사람의 생존/재직 조건을 검증한다. 날짜 자체를 선택의 성공 증거로 쓰지 않는다.

## 9. 통합 플레이 루프: 현장 하나에서 국가 전체가 연결되게

```text
① 현장/지도에서 실제 변화 발견
       ↓
② 관련 인물의 설명 + 과거 약속 + 계산 근거 확인
       ↓
③ 내 권한 안에서 배정·집행 / 권한 밖이면 상신·협의
       ↓
④ 인력·자원·기간을 예약한 같은 기존 명령 실행
       ↓
⑤ 주간 결산: 경제·작전·사회 상태를 한 번 갱신
       ↓
⑥ 현장 변화 + 인물의 기억 + 후속 현안으로 결과를 남김
       ↓
⑦ 필요 시 시대/보직 전환: 자산·사람·미해결 책임 인수
       └───────────────────→ ①
```

**하나의 검증용 시나리오:** 공세 부대의 실제 보급 부족을 발견한다. 담당 참모의 지원 요청과 남은 전력을 확인하고, 가용 생산/지원/공세 명령 중 하나를 바꾼다. 다음 주 같은 명령 ID의 결과에서 공급·진척·손실을 확인한다. 담당자는 실제 이행 결과를 기억한다. 문제가 계속되면 같은 현안이 악화되고 해결되면 종료된다. 이후 전후 전환에서는 남은 전력·국가 생산·미이행 약속의 처리 근거를 보여준다.

이 예시에서 **항만 점령→공장 정지 같은 지역적 인과는 2단계 지역 생산·물류 모델이 있을 때만 추가**한다. 현재 데이터가 보급 지표 수준이면 그 수준에서 설명한다. 플레이어가 예상한 해결 효과와 실제 결산이 다르면 확률·다른 요인·부족한 권한을 구분해서 보여준다.

선택 하나에 모든 참모와 모든 지표가 반응할 필요는 없다. 첫 화면은 중요한 변화 1개, 관련 사람 1~3명, 실행 가능한 선택 1~3개에 집중한다. 나머지는 펼쳐 보는 근거로 둔다. 이는 구현 초기의 정보량 제안이며 인물 수나 선택 수를 엔진 규칙으로 고정하라는 뜻은 아니다.

## 10. 확장 조사 이후에도 유지할 3단계 구현 경계

| 단계 | 실제로 묶을 것 | 하지 않을 것 | 다음 단계 진입 조건 |
| --- | --- | --- | --- |
| **1. 이번 소규모 현장 패널** | 생산/작전/참모를 원본 상태에서 투영. 실제 행동 1개와 결산 1개를 연결. Total War식 유효 지원선, HOI식 보급 근거의 작은 표현 | 새 물류망·의회·실시간 전술·별도 사건 엔진을 한 번에 추가 | 현장/기존 UI 값과 권한 동일, 렌더/재생 무부작용, 고정 시드 결과 동일 |
| **2. 지도 지역 생산 현장** | 문명·Victoria 3의 공간/생산 원리와 HOI의 병목 원리를 우리 지역 모델로 통합. FM식 목표와 XCOM식 배속은 기존 업무 하나에 먼저 적용 | 국가 자원을 각 지역에 중복 지급, 가짜 시설 위치·노선, 모든 공장 수동 조작 | 국가/지역 장부 보존, 소유권 변화·수리·파견 중복 방지, 구세이브 이전 검증 |
| **3. 인물 회의장과 지속 현안** | 삼국지식 결정 공간, CK3식 근거 있는 기억, FM식 약속 검증, Stellaris식 진행 현안, RimWorld식 노출 리듬. 사회 대표 모델이 준비된 범위에만 Frostpunk식 이해 조정 | UI 전용 호감도/의석, 연도별 강제 위기, 무한 팝업, 모든 국가 동일 체제 | 같은 안건 1회 집행, 참석·권한·지식 일치, 후속 기억 근거 추적, 전환 시 장부·책임 보존 |

**기능 추가를 멈추는 기준:** 새 아이디어가 기존의 현장→행동→결과→기억 흐름에 들어오지 않고 별도 자원·점수·메뉴만 요구하면 보류한다. 새 메커닉 하나를 넣을 때는 중복된 기존 조작/알림 하나를 통합할 수 있는지도 검토한다. 움직임·이벤트·대사량이 아니라 플레이어가 결과의 이유를 설명하고 다음 행동을 결정할 수 있는지로 평가한다.

### 공통 회귀 검증 항목

- 같은 시드·같은 명령이면 현장 화면 유무, 확대/축소, 연출 생략, 저장/불러오기에 관계없이 같은 결산이어야 한다.
- 임무 파견/전투 배속/회의 참석의 겹침은 실제 가용성 규칙으로 처리하며, 화면이 사람을 복제해서 해결하지 않는다.
- 약속·사건·전환의 중복 식별자를 재처리해도 비용·신뢰·보상이 두 번 적용되지 않아야 한다.
- 원인 사건이 없거나 인물/영토가 유효하지 않으면 잘못된 장면 대신 근거 부족·미배정 상태를 보여준다.
- 지역화·체제 전환·사람 교체 후에도 재고·생산력·부채·미해결 약속의 처리 내역을 추적할 수 있어야 한다.
- 정적/접근성 모드에서도 무엇이 진행 중인지, 어떤 비용과 기한이 있는지, 어떻게 개입하는지 같은 정보를 얻어야 한다.

이번 확장은 **설계 조사 문서만 변경**한다. 여덟 원리를 추가로 검토했다는 것은 여덟 시스템을 구현했다는 뜻이 아니며, 기존 3단계 로드맵을 무제한 기능 목록으로 확장하지 않는다.
