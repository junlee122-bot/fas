# Command Edition 6 — 후보 조사·영입 작업대

작성: 2026-09-10. [CE5 제도 업무공간](command-edition-5-institutions-2026-09-10.md)에 이어 조직 운영의 **후보 시장 → 조사 → 접촉 → 조건 협상 → 실제 임명**을 정리했다. 이번 묶음은 새로운 역사 인물이나 사건의 수를 늘리는 작업이 아니라, 기존 인사 시스템의 판단과 결과를 이해할 수 있게 만드는 단계다.

## 달라진 플레이 흐름

| 단계 | 화면과 실제 처리 |
|---|---|
| 후보 찾기 | 검색·전문 분야·시장 범위·정렬, 24명씩 페이지 탐색. 후보 선택과 보고서 열람은 무료다. |
| 조사 업무 | 사용 중/전체 슬롯, 빈 슬롯, 매주 증가량, 완료 예상 주수, 진행 중·완료 보고서 바로가기를 제공한다. |
| 조사 착수 | 정치력 2, 즉시 정보 +8을 먼저 검토한다. 승인 후에만 조사에 착수한다. |
| 자동 조사 | 실제 주간 엔진에서 정보 +18. 인사 업무를 위임하면 +23, 슬롯도 2→3개다. 주간 자동 조사에는 추가 정치력을 쓰지 않는다. |
| 관심 명단 | 조사와 별개로 등록·해제한다. 관심 등록 때문에 진행 중 조사가 끊기지 않는다. |
| 조사 중단·완료 | 중단은 무료이며 확보 정보와 관심 여부를 유지한다. 재착수 비용은 2. 정보 100에 도달하면 슬롯을 반환하고 보고서를 남긴다. |
| 비밀 접촉 | 정치력 4, 정보망 25 이상, 정보 30 이상, 같은 인물 주 1회의 조건과 관계·관심·경쟁 압력·정보 변화를 보여준다. 정보망은 소모하지 않는다. |
| 조건 협상 | 권한·임기·주급·계약금·약속을 조정한 뒤 비용·인사 영향을 검토한다. 인라인 작업대이므로 배경을 가리는 별도 협상 모달은 없다. |
| 최종 승인·확인 | 실제 명부에 새 참모가 반영되거나 실제 후보 기록에 결렬 결과가 남아야 결과 확인을 표시한다. 콜백 호출 자체를 성공으로 간주하지 않는다. |

### 잘못된 확률 안내를 실제 판정으로 교체

기존 판정은 난수 추첨이 아니라 설득 점수 **72점 이상이면 합의**하는 규칙이었다. 이를 성공 확률처럼 보이게 하던 표현을 제거했다. 기본 조건 점수는 실제 기본 제안(집행 권한·104주·요구 보수)을 기준으로 계산해 목록과 협상 화면을 일치시켰다.

- 성공: 정치력 6 + 계약금, 같은 부서의 **현직자 교체**, 기존 주급을 새 주급으로 대체한다.
- 결렬: 정치력 3, 계약금 미지출, 현직자 유임. 다음 요구 기본 계약금 +12와 관계·관심·경쟁 압력 변화를 미리 표시한다.
- 제출 자격은 기존처럼 정치력 6과 전체 계약금 보유다. 결렬 예상이어도 자격과 실제 지출을 구분한다.
- 임명 검토에서 전임자·후보·임기·조직 전체 주간 인건비·책임 위임 초기화를 보여준다. 약속은 게임 내 계약 조건이며 실제 자원·승계권·법적 신변보장을 즉시 주는 행동은 아니라고 명시한다.
- 통화는 게임의 국가 화폐 포맷을 사용하며 검토 전후 잔액은 정밀 표기로 표시한다. 내부 회계 숫자와 표시 화폐가 섞이지 않도록 했다.
- 기존 내부 추천·정렬 API의 호환 필드는 유지한다. 이것이 무작위 협상 엔진을 새로 구현했다는 뜻은 아니다.

## 엔진과 저장 안전성

새 순수 인사 엔진을 App의 실제 실행과 화면 검토가 함께 사용한다. 전시 및 전후 주간 흐름 양쪽에 조사 진척을 연결했고, 완료 이벤트는 주간 기록에도 남는다.

1. 완료된 구 저장의 조사 상태를 정규화하여 슬롯을 반환한다. 관심 여부는 선택적 `shortlisted` 필드로 분리하고 구 저장의 `status: shortlisted`를 읽는다. 저장 버전은 **38**을 유지한다.
2. 조사 중 다시 착수해 비용을 반복 차감하는 요청을 막는다. 중단 후 재개는 별도 명시적 조치다.
3. 주차·자원·보직·직급·국가 ID·후보 신원·현직 신원·제안 조건·주간 진행 여부를 검토 및 승인 시 검사한다.
4. 검토 후 상태가 바뀌면 승인하지 않는다. 동일 명부가 반영되기 전에는 서로 다른 인사 요청도 한 건만 전달해, 비용은 중복 차감되면서 명부가 덮어써지는 경로를 막는다.
5. 임명 대상이 없거나 여러 현직자가 같은 보직에 있으면 비용을 쓰지 않는다. 현재 참모를 다시 중복 임명하지 않으며, 전임자의 기존 시장 기록이 있을 때는 실제 교체된 기록 하나만 남긴다.
6. 새 인물은 전임자의 면담 잠금·책임 위임·집중 육성 지정을 자동 승계하지 않는다. 현재 참모를 세대 등장 후보로 다시 추가하는 경로도 제외한다.
7. 승인 게이트는 전체 캠페인의 거대한 후보 스냅샷을 무한 누적하지 않고 현재 상태만 유지한다. UI는 게이트 내부 저장 방식 대신 공개 상태 조회 함수를 사용한다.

인물의 정보 100%는 **게임 내 조사 진행도**다. 사료의 완전한 검증이나 실제 역사적 임명 가능성을 보장하지 않는다. 기존 역사 자료 링크와 미확인 전시 소속·소재 등의 주의 문구를 유지했으며 이번 작업에서 새로운 역사 조사나 수천 회 장기 시뮬레이션을 수행했다고 주장하지 않는다.

## 로컬 실제 플레이 검증

`http://127.0.0.1:4197/` 전용 자동화 브라우저에서 영국 최고 정치직으로 새 캠페인을 생성했다. 아래 결과는 저장값으로 결과를 주입한 것이 아니라 **화면 조작과 실제 주간 진행**으로 만들었다. 숫자는 별도 표시가 없으면 내부 회계 단위다.

데스크톱은 1440×1000에서 조사·임명 검토·실제 결과를 확인했다. 모바일에서 기존 필터 라벨의 고정 높이 30px 때문에 44px 선택 상자가 다음 행 아이콘과 겹치는 문제를 발견했다. 라벨을 내용 높이에 맞추고 좁은 화면의 중복 필터 아이콘을 제거했다. 수정 후 전문 분야 라벨 67.19px 안에 선택 상자 44px가 들어가며 다음 필터와 16px 간격을 유지한다.

React 스킬에 따라 파생 검토와 실행을 분리하고, 브라우저 검증 스킬로 UI뿐 아니라 실제 저장 명부·자원·키보드 포커스·반응형 배치를 확인했다. 브라우저 페이지 오류는 0건이었다. 자동화 브라우저의 기존 저장 키·값은 검사 후 복원했다.

## 최종 검증

- `npm test -- --maxWorkers=2`: **122개 파일 · 1,579개 테스트 통과**(90초). CE5 대비 149개 증가했다. 주차 표기를 내부 0부터가 아닌 화면의 제1주 기준으로 고친 뒤 관련 기대값도 갱신하고 전체 시험을 다시 통과했다.
- TypeScript 및 `npm run build:pages` 통과. 큰 청크 경고는 남는다. 메인 JS 3,107.28kB(gzip 977.64kB), 공통 CSS 871.83kB. 조직 화면 JS 93.20kB, CSS 57.34kB로 지연 로딩한다.
- `git diff --check` 통과. 기존 LF/CRLF 정규화 경고 외 변경 오류는 없다.

커밋·배포는 기존 사용자 요청대로 GPT-5.6 Luna가 기존 브랜치와 GitHub Pages 워크플로를 사용한다. 지도 삽화의 용량·해상도를 줄이지 않았으며 무관한 원자료·이미지는 커밋에 포함하지 않는다.

## 다음 묶음 — 사용자 커리어 제안과 참모 계약

이번 작업은 후보 영입의 완성도를 올린 것이며 전체 조직 운영 또는 FM식 경력을 모두 완성한 것은 아니다. 최종 감사에서 확인한 후속 범위:

- 사용자가 받는 국가·정보기관의 제안도 조건 검토→응답→실제 소속/권한 변경 확인으로 통일한다.
- 만료된 제안의 엔진 응답 차단, 무제한 재협상으로 계약금·보호·권한·기한을 계속 늘리는 경로를 수정한다.
- 자발적 경력 접촉의 정치력 비용·자격을 UI와 엔진에서 일치시킨다.
- 공식 보직의 급여와 비밀공작 보수를 구분하고, 국가 이동 시 바뀌는 자원·참모진·부대·외교·경력 수치를 설명한다.
- 제안이 사라졌을 때 다른 제안을 자동 선택하지 않도록 한다.
- 기존 참모의 승급·재계약·보직 변경은 별도 검토와 결과 확인을 추가할 대상이다. 이번 후보 조사·영입 개편만으로 이들 원클릭 조치까지 정리했다고 표현하지 않는다.
- 큰 메인 번들과 공통 CSS, 실제 면담·갈등 장면의 다양성, 상대국 협상 AI는 여전히 후속 과제다.
