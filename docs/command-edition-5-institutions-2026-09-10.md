# Command Edition 5 — 헌정·권한·사법 업무공간

후속 구현: [CE6 후보 조사·영입 작업대](command-edition-6-personnel-2026-09-10.md). 조사 슬롯·관심 명단, 실제 협상 판정과 인사 교체 결과를 연결했다. 사용자 국제 커리어 및 기존 참모의 계약 관리는 다음 범위로 구분한다.

작성: 2026-09-10. [이전 CE4](command-edition-4-diplomacy-intelligence-health-2026-09-08.md)의 깊은 하위 보드 정리 과제 중 헌법·사법 인사, 국가 권한, 수사·재판을 구현했다. 콘텐츠 개수 확대가 아니라 기존 선택을 이해하고 안전하게 집행하는 흐름에 집중했다.

## 플레이어에게 달라지는 것

| 업무 | 개편한 흐름 |
|---|---|
| 헌정·사법 진입 | `제도 업무 일정`에서 지금 응답할 결재와 주간 진행을 기다릴 심사를 구분한다. 해당 사건·인사 절차·검증 장부로 바로 이동한다. |
| 헌법·인사 | 헌법 초안 / 사법 인사 / 절차 진행 / 기록. 한 장·한 보직·한 후보를 선택하고, 비용·실제 지표 변화·시점을 검토한 뒤 승인한다. |
| 국가 권한 | 법률·헌정 / 정부·위기 / 국가·외교 / 귀족·영지의 기존 27개 권한을 모두 열람한다. 권한 행사와 검증 장부를 분리한다. |
| 수사·재판 | 사건 목록 / 현재 결재 / 신규 제보 / 기록. 열람 중인 사건과 실제 결재 대상을 구분하고, 잘못된 사건을 승인하지 못하게 한다. |

이동과 목록 선택은 무료다. 비용을 쓰는 버튼은 검토 이후 별도 승인을 요구한다. 인사 지명은 임명이 아니며, 사건 인지·본수사·증거력은 유죄 확정이 아니다. 검증 예정일도 자동 성공일로 표시하지 않는다.

### 실제 조건을 설명하는 검토안

- 기존 순수 엔진으로 계산한 결과를 보여주되, 승인 전에는 게임 상태를 바꾸지 않는다. 정치력·국고 부족, 보직·국가 불일치, 유효하지 않은 직급, 현재 단계와 다른 결재를 차단한다.
- 주차·보직·대상·수치가 바뀐 검토안은 승인할 수 없다. 상태 반영 전 연타와 동일 인사·사건의 다른 처리안을 연달아 보내는 중복 요청도 방어한다.
- 헌정·사법·정통성·공공 신뢰 등의 0–100 상한을 적용한 실제 전후값을 표시한다. 기본값을 지어내는 대신 필요한 국정 지표를 부모 화면에서 전달한다.
- 승인 화면의 국고는 정밀 표기를 쓴다. 브라우저에서 지명 비용은 보이지만 현재/지출 후 잔액이 모두 `£9.3억`으로 반올림되던 문제를 발견해 수정했다. 상단 핵심 자원의 간결한 요약은 유지한다.
- 월권은 합법적 권한과 구분하고 위험 확인을 추가한다. 영지 권한에는 사용자가 명시적으로 고른 작위·영지 보유자를 사용하며, 사라진 대상을 다른 인물로 자동 대체하지 않는다.
- 헌법 조항 이름에 내부 ID가 드러나던 권한 근거를 한국어 조항명으로 바꿨다. 가상 법조인은 실제 역사 인물인 것처럼 표시하지 않는다.

### UI 밖에서도 막은 엔진 문제

1. 이미 채택한 동일 헌법 조항을 다시 제출하면 기존 실패 계약인 `null`을 반환한다. 비용·상태·기록을 바꾸지 않는다. 다른 조항으로 수정하는 비용은 정치력 1로 유지했다.
2. 일반 사법 인준은 정치력 2가 있어야 한다. 0·1일 때 직접 엔진을 호출해도 실패하며, 정확히 2일 때는 정상 인준한다. 강행·보강검증·철회의 다른 비용과 심사 일정은 유지했다.

저장 스키마는 기존 버전 38을 유지한다. 헌법 비준 자체는 기존 엔진처럼 승인 즉시 공포되며 별도 국민투표 대기 기간을 새로 구현한 것은 아니다.

## 로컬 실제 플레이 확인

`http://127.0.0.1:4197/`의 전용 자동화 브라우저에서 영국 최고 정치직으로 시작했다. 아래 과정은 저장 상태를 주입한 가짜 결과가 아니라 UI 조작과 실제 주간 엔진으로 확인했다. 국고 수치가 숫자로 적힌 행은 내부 게임 회계 단위다.

| 조작 | 관측 결과 |
|---|---|
| 의회책임 내각제 검토 | 정치력 120 유지, 아직 초안 미채택 |
| 조항 승인 | 정치력 120→119, 초안 1/7, 같은 조항 재채택 버튼 비활성 |
| 대법원장 후보 지명 | 정치력 119→107, 국고 920→912, `vetting`, 다음 심사 내부 week 2 |
| 독립 특별검사 결재 | 정치력 107→102, 국고 912→904. 사건은 `investigation`, 다음 검토 내부 week 3, 결재는 해소되지만 사건은 미결 |
| 법률 공포·재가 | 정치력 102→100, 권한 자본 62→60, 2주 뒤 검증 기록 생성 |
| 2주 실제 진행 | 후보 `hearing`, 한 주 뒤 인준 예정. 권한 기록은 `resolved: true`와 실제 결과 문장을 얻음 |
| 3주 실제 진행 | 업무 일정에 대법원장 인준 판단 표시. 안내에서 인사 절차로 직접 이동 |
| 인준 승인 | 정치력 109→107, 임명 기록 생성, 진행 중 인사 종료, 공석 6→5 |
| 검토를 연 채 다음 주 진행 | 권한 승인 버튼 비활성, 최신 상태로 다시 검토하라는 안내. 검토 당시 보직·주차도 보존 |
| 뇌물 거절·접촉 기록 | 정치력 1·국고 1 비용을 검토 후 승인. 본수사는 계속되며 다음 절차 주차가 갱신됨 |
| 새 제보 `국내 감찰·세무자료 정치 악용` 접수 | 별도 승인 후 새 사건과 그 사건의 관할 결재가 생성됨 |
| 새 사건 결재 중 예전 포탄 사건 열람 | 대상 불일치 안내와 올바른 사건으로 이동 버튼만 표시. 다른 사건 이름으로 결재할 수 없음 |

회귀 시험은 전시·전후 진입, 13개 국가의 하위 보직 안내, 권한·자원 경계, 모든 기존 권한의 순수 엔진 전망, 중복·오래된 검토·불일치 대상, 실제 심사 상태 변화 등을 다룬다. 이 작업에서 전 국가 수천 회의 장기 시뮬레이션을 새로 수행했다고 주장하지 않는다.

## 시각·접근성 마감

- 데스크톱 1440×1000, 모바일 390×844의 네 업무 화면을 직접 확인했다. 모바일 문서 너비는 390px이며 검사한 보드 내부 요소에 좌우 넘침이 없었다.
- 모바일에서 사건·권한의 긴 목록을 선택 상자로 바꾸고, 검토와 조작은 단일 열로 배치했다. 본문과 제목, 비용, 위험 안내, 키보드 포커스를 분리했다.
- 승인 후 사법 화면의 포커스가 현재 결재 상태로 돌아오는 것을 확인했다.
- 주간 진행 중 드러난 공통 위기 띠의 글자 잘림도 수정했다. 이전 고정 그리드 행은 새 폰트와 여백을 수용하지 못했다. 이제 내용 높이로 행을 계산하고 긴 전선명도 줄바꿈한다. 데스크톱 높이 63px, 모바일 84px에서 텍스트가 띠 내부에 들어오는 것을 계측했다.
- React 스킬에 따라 파생 검토값과 실행을 분리하고 세 하위 보드를 지연 로딩했다. 브라우저 검증 스킬로 실제 조작·저장값·반응형 화면을 함께 확인했다.

## 검증 및 남은 범위

- 전체 회귀 시험: `npm test -- --maxWorkers=2`, **119개 파일 · 1,430개 통과**. CE4의 1,155개보다 275개 증가했다.
- TypeScript 및 `npm run build:pages` 통과. `git diff --check`도 통과했다(줄바꿈 정규화 경고만 있음). 최종 메인 JS 3,094.89kB(gzip 973.90kB), 공통 CSS 871.83kB이며 큰 청크 경고는 남아 있다. 지도 삽화의 해상도를 낮추지 않았다.
- 브라우저 페이지 오류 목록은 0건이다. 검사 종료 후 전용 자동화 브라우저의 기존 저장 키·값을 모두 복원하고 QA 캠페인이 남아 있지 않음을 확인했다. 사용자 일반 브라우저의 저장은 사용하지 않았다.
- 이번 묶음은 제도 업무를 정리한 단계이며 전체 리디자인 완료를 뜻하지 않는다. 상대국 협상 AI, 여러 주에 걸친 정보공작, 인물 경력·친밀도 장면, 무기 수명주기와 실제 법안·선거 간 연결은 별도 후속 과제다.
- 국가 권한의 이름이 같더라도 해당 버튼은 현재 권한·국정 지표와 검증 기록을 다루는 추상화다. 특정 후보 임명, 실제 선거 실시, 새 작위 서임은 각 전용 체계를 이용한다.
- 메인 번들 약 3.1MB와 큰 공통 CSS는 여전히 구조적 과제로 남는다. 이번 세 하위 보드의 분리만으로 전체 성능 문제가 해결됐다고 표현하지 않는다.
- 커밋·GitHub Pages 배포는 이전 사용자 요청대로 GPT-5.6 Luna에게 맡긴다. 기존 브랜치와 워크플로를 사용하며, 무관한 원자료·스크린샷을 추가하거나 `main`을 변경하지 않는다.
