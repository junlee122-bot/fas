# 액티브 월드 구현 결과 — 작전·참모 회의·지역 물류

작성일: 2026-09-08. 이전 [설계 계약](active-world-next-slices-2026-09-08.md)의 A1·A2·B1·C1·C2를 로컬 게임에 연결했다. 단순 목업이 아니라 기존 주간 엔진, 비용, 재고, 권한, 저장을 사용한다. B2 정량 이행 약속과 여러 경유지를 가진 실제 물류망은 아직 후속 설계다.

## 1. 어디에서 플레이하는가

| 화면 | 이번 구현 | 실제 상태 변화 |
| --- | --- | --- |
| 합동군 → 작전 현장 | 배속·지휘관·목표·진척·연결 교전 결산·중단 요청 | 다음 주 교전 전 중단, 상태 해제, 중단 기록 |
| 조직 운영 → 참모 회의실 | 실제 당사자·현안 근거·선택·결재 전 확인·후속 기록 | 기존 인물/관계/정치력 효과를 한 번 적용하고 기존 기한에 검증 |
| 산업 전환 → 지역 집하·수송 | 선택형 거점·품목·용량 구성, 창고/운송/가용 분리 | 새 전후 생산의 귀속, 창고에서 예약, 주간 운송, 실제 도착 입고 |

작업대를 분리해 참모 관리와 회의, 편제와 작전, 생산과 물류를 한 화면에 모두 쌓지 않는다. 지휘 본부의 참모 현장에서도 회의로 이동한다. 지도 위 승인된 공세 목록에서 작전 현장으로 이동할 수 있다.

## 2. 작전: 명령에서 중단·결산까지

- 새 지상 공세는 안정적 명령 ID를 가진다. 동일 부대가 같은 목표를 다시 공격해도 과거 공세 결산을 섞지 않는다.
- 구세이브의 명령 ID를 보완하되 누적 진척을 초기화하지 않는다.
- 교전 보고에 작전 ID, 실제 적용 손실, 실제 적용 항공지원, 최초 승인 지휘비용을 연결한다. 옛 기록에서 확인 불가능한 값은 자료 없음/계산값으로 구분한다.
- 중단은 요청 즉시 승리·이동·환급을 만들지 않는다. 다음 주 해당 부대의 교전 전에 중단하고, 원시 부대 상태의 status만 해제해 장비 보정이 중복 적용되지 않게 한다.
- 지도 선택과 승인 명령은 분리된다. 화면을 열거나 선택하는 것은 공세를 재실행하지 않는다.
- 동일 주의 재입력·주간 진행 중복 요청을 방어한다. 대규모 작전 ID도 상태 updater 밖에서 한 번 만들고 승인한다.

정치가의 화면 접근권과 야전부대 지휘권은 다르다. 브라우저 검증에서도 비군사 보직에서는 중단 버튼이 비활성화됐고, 해당 부대를 지휘하는 군사 보직에서만 요청할 수 있었다. 합동 해공군 작전 중단은 이번 범위가 아니다.

## 3. 회의: 선택의 근거와 사람의 책임

현재 재직 인물과 원본 현안만 회의에 나타난다. 내부 사정과 실제 사건 연결을 구분하며, 재구성 의견을 역사적 직접 인용처럼 표시하지 않는다.

선택지 열람 → 비용/인물 변화 확인 → 최종 결재 → 원본 기록 → 예정 주간 검증 순서다. 검토 도중 인물·정치력·권한·주차가 바뀌면 다시 검토해야 한다. 별도 회의비나 참석 보상은 없다.

결정 당시 staffId뿐 아니라 personId와 이름을 저장한다. 교체된 후임자, 퇴임 인물, 신원 연결이 없는 옛 기록은 검증 불가로 보존한다. 예정 날짜에 도달했다는 이유만으로 성공 처리하지 않는다. 검증 때 측정한 사기·수용·역할 만족도도 남긴다.

버전 37 저장은 명시된 참모 명단을 우선한다. 부분 명단을 불러올 때 과거 역사 인물을 공석에 다시 생성하지 않는다. 구버전의 누락 자료 보완은 기존 migration 경로를 유지한다.

## 4. 물류: 생산 완료와 국가 가용은 다르다

기본값은 기존 국가 직납이다. 사용자가 시범을 켜면 보병 장비·전차·항공기·야포·차량 중 한 품목의 새 전후 생산을 지정 창고에 모은다. 기존 비축은 복사하거나 잠그지 않는다. 함선·수송선은 이 추상 육상 연결 시범에서 제외한다.

한 주 처리 순서:

1. 기존 예약/운송을 진행하고 실제 도착만 국가 가용량에 더한다.
2. 이번 주 공장 생산 완료분을 선택 창고 또는 국가 직납에 귀속한다.
3. 국가 가용 재고만 장비 준비도·부품 공급에 전달한다.

보존식은 국가 가용 + 미예약 창고 + 예약/운송 중 = 총보유다. 이전 생산 원본이나 도착 영수증을 다시 처리해도 재고를 더하지 않는다.

직접 소유, 실제 통제 진영, 현 지도 거점, 인접 연결, 국가 역량을 확인한다. 경로가 차단되면 화물을 삭제하지 않고 보류한다. 신규 집하를 중지해 기존 물량을 처리할 수 있다. 잘못된 저장의 지역 계정은 원본을 격리 보존하며 수량을 추정하지 않는다.

국가 이동 때 이전 국가의 창고·화물은 이전 국가 계정에 남고 새 국가 재고가 되지 않는다. 완료/취소 기록은 최근 120개, 원본 ID는 최근 128개로 제한하되 모든 활성 화물과 마지막 도착 근거, 마지막 처리 주차는 보존한다.

### 시범의 명확한 한계

- 실제 공장 위치나 역사적 철도·도로를 조사해 배치한 지도가 아니다. 기존 전략지도 좌표·인접 관계를 이용하는 플레이어 지정 집하 연결이다.
- 여러 노선, 철도 게이지, 항만 환적, 해상 호송, 운임, 적의 수송 공격은 이번 시범에 없다.
- 예약은 수동이다. 자동 예약이나 자동 배송 지시를 추가했다고 표시하지 않는다.
- 한 주 출발 용량과 현재 예약 가능량, 창고 전량 처리 최소 기간을 표시한다. 재고가 남은 동안 경로·품목·귀속 역량을 바꾸는 기능은 제한된다.
- 모식도와 아이콘은 UI 표현이며 새로운 3D 전투 시뮬레이션이 아니다.

## 5. 검증

### 자동 검사

- 전체 101개 파일, 710개 테스트 통과.
- 기존 612개 테스트 기반에서 명령 연결/중단, 인물 동일성, 회의 UI, 물류 보존/저장/긴 기간, 실제 가용 부품 공급을 보강했다.
- TypeScript 검사 및 npm run build 통과. 마지막 UI 회귀 16개도 재검증했다.
- git diff --check 통과. 기존 대형 번들 경고는 남아 있으며 지도 원본 해상도나 삽화 용량을 줄이지 않았다.

### 실제 브라우저와 주간 엔진

127.0.0.1:4197에서 기존 저장을 백업하고 명시적 QA fixture를 만들어 조작했다. 이는 사람처럼 수백 번 장기 플레이했다는 주장이 아니라, 특정 기능의 실제 화면·저장·주간 경로 통합 검증이다.

## 6. 후속 구현 순서 — 아직 구현했다고 주장하지 않는 것

1. **안건 단위 상신**: 특정 현안·당시 인물·선택지·비용 한도를 고정한 요청, 심사 후 최신 상태 재검증. 화면 접근 위임과 개별 안건 승인을 분리한다.
2. **B2 정량 약속**: 담당자·생산 라인·기한을 명시하고 실제 생산/도착 영수증의 어느 지표를 약속했는지 구분한다. 담당 교체 때 자동 인계하지 않는다.
3. **수송 운영 정책**: 사용자가 승인한 자동 예약, 적체 시 용량 조정, 명시적 목적지 변경. 총량 보존과 원본 명령 한도를 유지한다.
4. **근무 구간 기록 보관**: 국가·serviceId별 참모 사건 및 작전 기록을 과거 열람용으로 보존한다. 현재 국제 이동 후 새 참모 서사가 시작되는 것과 구분한다.
5. **지도상 물류망 확장**: 실제 사료에 근거한 거점·운송 방식, 여러 경유지, 위험과 대체 경로. 이번 추상 연결의 이름만 바꾸어 역사적 노선이라고 주장하지 않는다.

참고한 게임들의 구체 설계 근거는 [기존 액티브 월드 조사](active-world-design-research-2026-09-08.md)에 유지했다. 이번 구현은 그 조사에서 제안한 FM식 사람-책임, 작전 추적, 생산-수송-가용 구분을 현재 엔진 범위에 맞게 좁혀 적용한 것이다.
