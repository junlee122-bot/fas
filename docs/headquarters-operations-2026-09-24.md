# 연결된 기관 운영 — 구현 및 검증

## 이번 변경

세계지도와 기존 상세 메뉴를 유지하면서 지휘부를 실제 상태와 지시가 연결되는 조작 계층으로 확장했다. 전체 게임의 후속 방향은 [공간 기반 게임 설계](./spatial-gameplay-design-2026-09-24.md)에 구분해 정리했다.

- 8개 기관에 현재 업무, 점검 상태, 투입 조건, 처리 과정, 결과 확인 경로를 표시한다.
- 방위 역량(연구→생산→창고→작전), 민생·재정, 사람·조직의 세 연결도를 선택할 수 있다. 노드는 해당 방을 선택하며 명령을 자동 집행하지 않는다.
- 연구실에서 정확한 과제를 고르고 시작·중지를 검토한 뒤 승인한다. 실제 진행도와 슬롯을 사용하고, 연구 속도가 없으면 완료 시점을 약속하지 않는다.
- 생산 관리실에서 정확한 라인을 골라 군수·민수 역량 1개 전환을 검토하고 승인한다. 현재 배분과 효율 변화는 보여주되 생산 완료나 장비 수령을 뜻하지 않는다.
- 긴 기관 설명은 펼침 영역에 두고 현장 행동을 앞에 배치했다. 하단 행동 바와 기존 전체 화면 연결은 유지했다.
- 과거 전시 결산의 적자가 국정 단계에서도 현재 재정 위기로 반복 표시되지 않도록 수정했다. 과거 기록은 보관 결산으로 구분한다.

## 권한·상태 보존

검토와 실행 시 현재 국가·경력·보직·주차·권한·기간 진행 잠금을 확인한다. 해임·무소속·잘못된 경력 연결·열람/상신 권한으로 직접 명령을 실행할 수 없다. 기존 규칙상 유효한 임시 권한 위임과 복무 중 경력은 보존한다.

검토 당시와 연구·공장 상태가 달라지면 같은 검토안을 실행하지 않는다. 중복 ID, 없어진 과제/라인, 초과 슬롯, 선행 연구·시대 제한 등을 검사한다. 다른 대상 자동 선택이나 자동 재승인은 하지 않는다. 기존 연구·공장 처리 함수를 그대로 호출하며 선택 자체는 상태를 바꾸지 않는다.

현재 상태에서 도출할 수 있는 값은 별도 React 상태로 복제하지 않고 계산한다. 실제 엔진 기록에 없는 시설별 생산 공적·운송 성공·건물 파괴·인물 이동은 만들지 않는다.

## 자동 검증

최종 집중 회귀 검증: **12개 파일, 295개 테스트 통과**.

```text
npx vitest run src/HeadquartersFacilityWork.test.tsx src/HeadquartersWorkspace.test.tsx src/headquartersOperations.test.ts src/headquartersActionGuard.test.ts src/HeadquartersStaff.test.tsx src/staffWorkReport.test.ts src/CapabilityDesks.test.tsx src/livingWorld.test.ts src/nationalSimulation.test.ts src/researchProgression.test.ts src/StaffWorkReportCard.test.tsx src/staffDecisions.test.ts
```

`npm run lint` 및 `npm run build:pages` 통과. Pages 빌드는 기존 대형 청크 경고가 남아 있다(메인 JS 약 2.98 MB, gzip 약 0.94 MB). 번들 분할·초기 로딩 최적화가 완료된 것은 아니다.

검증용 TSX도 별도 타입 검사했다. `git diff --check`에 오류는 없으며 기존 작업 파일의 줄바꿈 변환 안내만 있었다. 별도 정적 검토에서 추가 실행 권한 우회나 잘못된 대상 대체 문제는 발견하지 못했다.

## 브라우저 검증

주소: `http://127.0.0.1:4197/scripts/verify-headquarters-operations.html`

실제 `HeadquartersWorkspace`를 메모리 상태로 렌더링하는 격리 화면이다. 사용자 저장을 읽거나 변경하지 않는다. 연구와 참모의 주간 부분 결산은 실제 함수를 사용하며, 전체 경제·전투 결산을 검증했다고 해석하면 안 된다.

1. 방·운영 흐름·연구 과제를 선택하고 검토해도 실행 콜백은 0회였다.
2. 연구 검토 후 주간 부분 결산을 실행하면 이전 승인이 사라지고 재검토 안내가 나타났다. 재검토·승인 후 선택한 암호 분석 과제만 시작됐고 연구 슬롯과 실제 누적량이 갱신됐다.
3. 보병 장비 라인의 민수 전환을 검토하면 배정 8→7개, 효율 84→80이 표시됐다. 승인 전에는 실제 상태가 바뀌지 않았다.
4. 검토 중 열람 전용으로 바꾸면 승인이 차단되고 현재 상태는 계속 읽을 수 있었다. 직접 권한으로 돌아와 재검토·승인한 뒤에만 군수 배정 14→13개, 민수 여력 16→17개, 공장 콜백/반영 각 1회가 확인됐다.
5. 기간 진행 중 잠금은 별도로 명령을 막았다. 실제 3단계 보직에서도 생산은 보고 열람, 연구는 상신 권한으로 구분되고 직접 승인은 불가능했다.
6. 1920×1080, 2560×1440, 3840×2160에서 배치도와 지시부를 시각 점검했다. 문서·지휘부·바닥 배치도·현장 지시부의 `scrollWidth`는 각각 `clientWidth`와 같아 가로 넘침이 없었다. 4K 우측 조작부는 부분 캡처로도 확인했다. 검증 후 화면 크기 설정을 복원했다.
7. 검증 탭에서 수집된 콘솔 오류·경고는 0건이었다.

## 아직 구현하지 않은 범위

개별 건설·증축·피해·복구, 실제 인물 이동, 일반인 전용 거점, 모든 생산물의 기관 간 단일 추적 화면은 후속 설계다. 기관 배치도는 현재 조직의 모식도이며 방 사이 거리는 운송 경로나 생산 보너스가 아니다. 기존 세계지도·저장 형식·주간 엔진을 이번 묶음에서 교체하지 않았다.

이번 변경은 로컬 작업 상태다. 커밋·푸시·배포는 실행하지 않았다.
