## 이전 평가에서 갱신해야 하는 부분

1. **첫 화면은 실제로 간결해졌다.** 영국 군사 보직의 기본 작업영역은 약 860자, 버튼 9개였다. 이는 사이드바·상단 조작부까지 포함한 전체 화면의 개수가 아니다. 상세 분석을 접고 현재 권한·우선 행동·예하 범위를 먼저 보여준다.
2. **권한 구분은 명목상이 아니다.** 직접/상신/보고 화면, 예하 부대, 부서별 인사권이 실제로 제한된다. 상급 참모의 자리도 보고만 가능하다고 표시한다.
3. **함대와 항공대가 존재하고 실제로 조작된다.** 호송사령부와 초계기를 묶어 작전을 승인하고, 퍼시 노블의 재량권 요청에 답신했다. 다주 작전과 적의 대응 계획도 이어졌다.
4. **참모 서사가 저장과 주간 진행에 연결됐다.** 관계 누적, 갈등 단계, 선택 효과, 후속 평가, 방치 시 공개 확산이 구현되어 있다.
5. **튜토리얼의 배경 조작 차단과 모바일 조직 폭 문제는 개선됐다.** 튜토리얼 중 접근성 스냅샷에 배경 버튼들이 계속 노출되던 이전 상태는 해소됐고, 이번 모바일 조직 화면은 작업영역 폭과 스크롤 폭이 모두 390px였다.
6. **가변 시간, 실제 음향, 시대별 주보가 있다.** 현재를 ‘주간 수동 클릭만 가능’, ‘소리 없음’, ‘후기 콘텐츠 없음’이라고 설명하면 부정확하다. 구현 깊이와 연결의 문제를 평가해야 한다.
7. **지도 시대 표기도 개선됐다.** 일부 미래 전선 명칭과 활성화가 연도·통제 변화에 따라 바뀌고 원도 연도를 구분한다. 다만 배경은 여전히 유럽 1944년·아시아 1943년의 고정 역사 스캔이며, 이것이 1942–2060 동적 국경지도 전체를 대체하지는 않는다.

## 출시 전에 우선 해결할 문제

### 1. 첫 실행 튜토리얼에 반복 상태 갱신 오류가 있다

**브라우저 관측:** 이번 새 캠페인 세션 콘솔에 `Maximum update depth exceeded`가 4회 기록됐다. 화면 조작은 계속 가능했으므로 영구 정지나 저장 손상까지 주장하지 않는다.

**코드로 확인한 순환:** 튜토리얼 effect가 화면 이동 → 역할 상호작용 기록을 새 객체로 갱신 → 권한 목록 재계산 → 화면 이동 함수 변경 → 튜토리얼 effect 재실행으로 이어진다. 이미 확인한 브리핑이어도 새 상태를 반환한다.

근거: [TutorialOverlay.tsx](../src/TutorialOverlay.tsx) 87–98행, [App.tsx](../src/App.tsx) 902–904 / 7927–7930 / 9155행, [roleCommand.ts](../src/roleCommand.ts) 217 / 234–246행.

**사용자 영향:** 가장 안정적이어야 할 첫 화면에서 불필요한 연속 갱신과 잠재적 입력 지연이 발생한다. 467개 테스트 통과와 별개인 출시 차단 수준의 통합 문제다.

**완료 기준:** 첫 진입부터 마지막 튜토리얼 단계까지 상태 변화 없는 재방문에서 추가 렌더링이 반복되지 않고 콘솔 오류가 없어야 한다.

### 2. 여러 육상 전선이 한 줄로 기다린다

**코드 확인:** 여러 사단에 명령을 넣어도 주간 육상 전투는 `orders[0]` 하나를 처리한다. 현재 명령이 끝나기 전까지 뒤 명령은 대기한다. 대규모 작전도 여러 명령을 등록하지만 같은 대기열을 사용한다.

근거: [App.tsx](../src/App.tsx) 2457 / 2808 / 2875 / 2925 / 5905 / 5928–5938행.

**사용자 영향:** 전선과 사단이 늘어나도 동시 공세·협공·증원 시점·전구 간 시간 경쟁이 충분히 성립하지 않는다. ‘대규모 세계전쟁’의 핵심 기대와 충돌한다.

적 육상 AI도 표적을 고르고 집결·탐색·공격하는 개선은 있지만 상태에 단일 작전계획만 두며, 별도의 적 지상 사단·생산·손실 재고를 운용하지 않는다. 따라서 ‘적 군단을 소모시켜 다른 전구의 대응을 늦춘다’는 전략 깊이는 아직 제한된다. [enemyStrategy.ts](../src/enemyStrategy.ts) 48–70 / 177–187 / 330–334행.

**완료 기준:** 독립 전선의 적격 명령들이 같은 주에 각각 진행되고, 같은 목표의 협공은 별도 합산·협조 규칙으로 해결되어야 한다.

### 3. 병력 수와 소모가 전투 판단을 배반한다

**실제 함수 재현:** 영국 전투기 집단의 기체 수를 0으로 바꿔도 항공우세 작전 예측은 **63% → 63%**, 경고는 없고 출격은 승인됐다. 현재 출격 검증과 전력 계산은 부대 종류·상태·준비도·경험을 보지만 기체/함정 수를 반영하지 않는다.

**실제 함수 재현:** 나머지 입력을 고정하고 수비 목표의 보급을 100에서 0으로 바꿔도 육상 전투 보고가 동일했고 우세도도 17로 같았다. 수비 피해는 목표 보급 감소로 저장되지만, 다음 수비 전력 계산은 그 보급을 읽지 않는다.

근거: [jointOperations.ts](../src/jointOperations.ts) 663–685 / 1277–1318행, [combat.ts](../src/combat.ts) 124–150행, [App.tsx](../src/App.tsx) 2876 / 2910행.

**사용자 영향:** 비싼 항공기를 지키고 적을 소모시키는 판단이 약해진다. 전쟁 게임의 핵심 자원에 대한 신뢰 문제다.

**완료 기준:** 0 전력의 출격은 막고, 병력 비율·손실·보급 고갈이 후속 전력·지속 시간·전투 결과에 일관되게 반영되어야 한다.

### 4. 합동지원·장비 준비도의 연결이 얕거나 어긋난다

**코드 확인:** 근접항공지원 성공은 모든 대기 명령에 `min(100, progress+12)`를 적용한다. 현재 진행 중인 첫 명령은 뒤의 주간 전투 계산에서 이전 명령을 바탕으로 다시 덮어쓰며, 대기 명령은 목표/전구와 무관하게 지원을 받는다. 공성 등 일부 명령의 목표 진척은 100을 넘는다.

또한 정비·장비 수명주기에서 관리한 항공·해군 카테고리 준비도가 합동작전 입력으로 들어가지 않으며, 지상 장비 효과도 주로 전력·조직·보급의 작은 보정으로 압축된다.

근거: [App.tsx](../src/App.tsx) 2414–2415 / 2837 / 2875 / 5738–5742행, [operations.ts](../src/operations.ts) 43–87행, [equipment.ts](../src/equipment.ts) 309–331행, [weaponReadiness.ts](../src/weaponReadiness.ts) 118–123행.

**사용자 영향:** 관리 항목은 많은데 ‘이 장비와 항공지원 때문에 이 전선이 바뀌었다’는 납득이 부족하다.

### 5. 전후 전환 뒤 주가·국가 프로그램 일부가 갱신에서 빠진다

**코드 연결 확인:** 국가 운영 단계는 전시 주간 함수에서 조기 반환한다. 전후 주간 처리에서는 부채·물가·신뢰·통화는 갱신하지만 회사 시장가격은 갱신하지 않는다. 회사 거래 화면은 계속 존재한다. 국가 프로그램의 6·13·26주 평가와 반복 검토도 전시 분기 내부에만 있다.

근거: [App.tsx](../src/App.tsx) 2135–2166 / 2398–2400 / 2437–2460 / 3091–3159 / 8744행, [economy.ts](../src/economy.ts) 332–344행.

이번 검토에서 전후 UI를 직접 재현한 결과가 아니라 호출 경로를 추적해 확인한 결함이다.

**사용자 영향:** 국가 운영이 본격적으로 중요해지는 시점에 투자와 장기 사업의 연속성이 끊긴다.

**완료 기준:** 각 시스템의 전시/전후 유지·변환·종료 규칙을 명시하고, 같은 저장 상태로 전환 직전과 직후를 넘긴 통합 테스트가 필요하다.

### 6. 달력과 실제 시스템의 연도가 다르다

**실제 계산 재현:** 시작일에 7일씩 더하면 week 10은 **1943-01-03**이고 뉴스도 1943년을 쓴다. 반면 여러 게임 시스템은 `1942 + floor(week/52)`로 계산해 1942년으로 판단한다. week 51의 표시 날짜 1943-10-17까지 차이가 남는다.

근거: [App.tsx](../src/App.tsx) 684 / 897 / 998 / 2137행.

**사용자 영향:** 인물·연구·통화·시대 화면이 열리는 시점과 표시 연도가 어긋날 수 있다. 대체역사라는 설정으로 설명할 수 없는 내부 시간 불일치다.

**완료 기준:** 날짜와 연도 판정을 하나의 공통 함수에서 가져오고 연말·윤년·시대 전환을 함께 검증해야 한다.

## 게임의 재미를 약하게 만드는 구조

### 7. 보직 성과가 실제 임무보다 화면 방문을 보상한다

**실제 함수 재현:** 영국 TIER 4 야전사령관 첫 주에서 군대 탭 방문에 해당하는 기록과 경제 보고 확인 한 번으로 목표가 완료됐다. 작전·생산·정책 실행 없이 다음 주 **경험 +5, 신임 +2, 평판 +1**을 받았다.

근거: [roleCommand.ts](../src/roleCommand.ts) 132–153 / 234–245 / 353–357행, [App.tsx](../src/App.tsx) 2351–2374 / 7927행.

권한 상신도 특정 작전·예산·정책의 승인보다 탭 전체를 몇 주 열어주는 방식에 가깝다. 월권의 즉시 신임·평판 비용은 실제로 있지만, 누적 불복 기록 자체가 해임·쿠데타 심사로 연결되지는 않는다.

**평가:** ‘내가 그 직업을 잘했다’보다 ‘주간 체크리스트를 지웠다’가 강하다. 목표·배정 자원·기한·평가자를 가진 실제 임무와 승진 심사가 우선이다.

### 8. 인물 사건에는 이름이 있지만 사건의 실체가 부족하다

**코드 확인:** 새 참모 서사의 유출 의혹·공로 다툼·승계 경쟁은 관계 수치와 인물쌍/주차 해시로 선택된다. 특정 작전 공적이나 실제 누설 문건이 원인 데이터로 존재하지 않는다. ‘독립 보안 조사’의 후속 검증도 증거·진범보다 당사자 사기와 지도부 수용도 평균으로 판정한다.

근거: [staffNarrative.ts](../src/staffNarrative.ts) 317–349 / 448–475 / 505–524 / 567–572행.

**평가:** 관계 누적은 진전이다. 그러나 인물을 기억하게 만드는 것은 ‘누구에게 어떤 승진을 빼앗겼는가’, ‘내가 승인한 작전에서 누구의 판단이 맞았는가’다. 실제 결정·작전·인물의 목표를 사건에 연결하고 그 결과가 사임·파벌 이동·누설·승계로 이어져야 한다.

### 9. 민간·첩보·사생활·사법은 서로 다른 삶보다 공용 행동표에 가깝다

- **민간:** 12직업이 공용 6행동과 쿨다운을 공유한다. 직업별 문구와 일부 영향 분야는 다르지만, 취재원·환자·사건 의뢰인·발명품 같은 고유 대상은 약하다. 감시 수치에 체포·실직·검열 같은 후속 분기가 연결된 경로를 찾지 못했다. [civilianCareer.ts](../src/civilianCareer.ts) 291–357 / 454–523행.
- **첩보:** 비밀 신분·핸들러·노출·탈출은 존재한다. 하지만 임무 응답은 제공·선별·가공·본국 통제·거부의 공통 루프로 돌아가며, 실제 현행 작전·연구·협상 정보를 고르는 깊이는 부족하다. [clandestineCareer.ts](../src/clandestineCareer.ts) 693–727 / 810–825 / 951–1005행.
- **사생활:** 같은 200주차에 ‘함께 시간’ 10회를 실제 비용과 함께 누적 적용했다. 국고 **892→832**, 국가 안정 **68→78**, 유대 **60→100**이 됐다. 모든 호출이 허용됐다. 개인 시간 제약이나 공무와의 충돌이 없어 국가 안정 구매 수단이 된다. [personalLife.ts](../src/personalLife.ts) 563–635행, [App.tsx](../src/App.tsx) 3949–3960행.
- **사법:** 수사가 뇌물 접근→검사 위협→언론 유출→기소 순서로 반복되고, 항소는 일정 기간 뒤 종결 처리에 가깝다. 실제 기업·참모·작전과 연결된 피의자와 반대 증거가 필요하다. [justiceSystem.ts](../src/justiceSystem.ts) 388–411 / 456–457 / 587–589행.

**평가:** 분야별 숫자를 더 추가하기보다 직업마다 다른 대상, 시간 사용, 실패 경험, 인물의 자율적 요구를 만들어야 한다.

### 10. 국가 경제 설명이 실제 규칙보다 더 깊은 시장을 약속한다

**코드 확인:** 국가사회·시장 스냅샷은 기존 국고·안정·산업 등에서 파생해 화면에 표시하며, 그 계층/상품 상태 자체가 다음 주 엔진 입력으로 돌아가지는 않는다. 경제 자체가 전부 가짜라는 뜻은 아니다. 세입·지출·부채·시장가격의 별도 실제 계산은 있다.

**실제 함수 재현:** 군수 공장 배정을 0→14→30으로 바꾸어도 소비재 공급은 **48.6**, 가격은 **126**, 주간수지는 **-7.1**로 같았다. 대조군 철강 공급은 **86.6→80.7→74.0**으로 변했다. UI 설명의 ‘군수 배정이 소비재 공급을 줄인다’는 연결은 해당 식에 없다.

근거: [nationalSimulation.ts](../src/nationalSimulation.ts) 207–249 / 327행, [App.tsx](../src/App.tsx) 1015–1029 / 8569 / 8635행.

**평가:** 시장과 계층을 보고 복잡한 국가 전략을 세우려는 사용자는 실제 인과가 어느 부분까지인지 알기 어렵다. 표시 설명부터 규칙과 일치시키고, 핵심 상품 몇 개에 생산·소비·재고·생활수준의 지속 피드백을 갖추는 것이 우선이다.

### 11. 시간 위임이 있어도 평시 진행은 자주 끊긴다

**실제 함수 재현:** 평온한 통제 상태에서 13·26·52주에는 모두 중립 `civic-review` 분기 평가가 발생했다. 12주에는 해당 이벤트가 없었다.

**코드 연결 확인:** App은 그 중립 보고도 사건이 있다는 이유로 기간 위임을 취소한다. 따라서 26/52주를 골라도 통상 13주 이내에 다시 시작해야 한다. 이 취소 연결은 브라우저 52주 연속 진행으로 재현한 것은 아니다.

근거: [nationManagement.ts](../src/nationManagement.ts) 733–754행, [App.tsx](../src/App.tsx) 2281–2289행.

**평가:** 120ms/주 배치 처리로 속도는 개선됐지만, 긴급하지 않은 보고와 진짜 의사결정의 정지 기준이 같아 긴 평시 캠페인의 리듬이 약하다. 중립 결산은 모아 보여주고 중대한 선택만 멈추는 편이 낫다.

### 12. UI의 읽는 부담과 세계 변화 연출은 여전히 남는다

**브라우저 관측:** 주요 보직 설명은 계산된 글꼴 크기 10px였다. 모바일 조직 가로 잘림은 해소됐지만 핵심 인사 조작까지 헤더·권한·전임자·주간 브리핑을 지나 긴 세로 이동이 필요하다. 어두운 작은 설명, 영문 보조 제목, 중복 수치도 자주 보인다.

**브라우저 관측:** 상단 ‘주간 브리핑 확인’을 눌렀을 때 내용을 열지 않고 읽음 처리 후 ‘다음 주’로 바뀌었다. 실제 주보 열기는 별도 사이드바 버튼으로 가능했다. 튜토리얼의 ‘창간호 확인’ 역시 주보를 여는 것이 아니라 다음 안내 단계로 넘어갔다. 문구와 행동을 분명히 구분해야 한다. [App.tsx](../src/App.tsx) 7477–7503행, [TutorialOverlay.tsx](../src/TutorialOverlay.tsx) 100–103행.

**브라우저 관측:** 영국 군사 보직에서 첫 주를 넘기자 독일의 ‘정권 전복·국가 양도 제안’이 전면 창으로 도착했다. 호송 작전과 참모진을 익히는 중에 극단적인 경력 분기가 개입한다. 이는 해당 테스트 세션의 관측이며 모든 국가에서 동일한 제안이 온다는 뜻은 아니다.

**코드 확인:** 미디어는 시대별 명칭·레이아웃·아이콘을 바꾸고 음향도 재생된다. 다만 소리는 여섯 종류의 짧은 합성 효과음이며, 도전과제 26개에 전용 삽화 자산은 8개다. 118년의 변화를 도시·신문 장면·인물·음악으로 체감하는 연출은 아직 얕다. [WorldWeekly.tsx](../src/WorldWeekly.tsx), [gameAudio.ts](../src/gameAudio.ts), [achievements.ts](../src/achievements.ts).

## 시뮬레이션 수치의 해석

기존 39,000/26,000회 자료는 가치 있는 조합·균형 검증이지만 현재 UI에서 그 횟수만큼 사용자가 플레이한 증거는 아니다. [possibilityMatrixPlaytest.ts](../src/possibilityMatrixPlaytest.ts) 299행 이후 자체 상태를 만들고 333행부터 12개 시대 가중 공식을 처리한다. 미래 고유성은 654–659행에서 시나리오·결말 지문을 구분한다. App 주간 진행 및 실제 선택 흐름과 동일한 모델이 아니다.

별도의 주간 엔진 교차검증 보고서는 존재한다. 이를 무시해서도 안 되지만, 조합 수와 ‘체감상 서로 다른 재미있는 캠페인 수’를 동일시할 수는 없다. 또한 7월의 700회 자료에서 얻은 전쟁 기간·결정 빈도는 9월 현행 개발본의 새 측정값이 아니다.

## 권장 수정 순서와 재평가 기준

| 순서 | 수정 목표 | 재평가에서 확인할 결과 |
|---|---|---|
| 1 | 튜토리얼 순환 갱신, 0 전력 출격, 손실/보급 반영, 다중 육상전, 합동지원 | 사용자가 화면에 보이는 전력·손실·시간을 믿고 계획할 수 있음 |
| 2 | 전시/전후 공통 진행, 연도 통일, 주가·국가 프로그램 연속성 | 같은 캠페인이 전환 후에도 일관된 규칙으로 지속됨 |
| 3 | 방문형 경력 보상·사생활 반복 버프 제거, 실제 업무 평가 | 버튼 반복보다 전략과 임무 성과가 유리함 |
| 4 | 실제 작전/정책과 연결된 참모 갈등·첩보·사법 사건 | 플레이어가 특정 인물·선택 때문에 벌어진 사건을 기억함 |
| 5 | 중립 보고의 비정지 누적, 첫 30분 전개, 조작 중심 화면 | 다음 목표와 주간 결산을 자연스럽게 이해함 |
| 6 | 시대별 지도/도시/인물/미디어 연출 | 다른 세계선이 플레이 도중 눈과 귀로 구분됨 |

재평가는 소수의 대표 루트라도 실제 UI에서 처음부터 전쟁/국가 전환까지 진행하고, 시작 10·30·60분의 목표 이해도, 첫 의미 있는 선택까지 걸린 시간, 반복 클릭, 불필요한 중단, 기억에 남는 인물·작전, 종료 후 다시 시작하고 싶은 이유를 기록하는 방식이 적합하다. 대규모 엔진 시뮬레이션은 이 검증을 보완해야 한다.

**현재의 구매 판단:** 기획과 시스템을 살펴보는 무료 프로토타입으로는 흥미롭다. 완성된 대전략 게임을 기대하고 구매하는 사용자에게는 아직 권하기 어렵다. 다음 점수 상승은 더 많은 인물·사건보다, 이미 존재하는 시스템들이 같은 전쟁과 같은 인생을 움직인다는 신뢰에서 나와야 한다.
