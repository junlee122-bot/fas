# 납품 목표의 생산·수송·실적 연결

## 이번 묶음의 결과

기관을 오가며 한 목표를 확인하는 첫 적용으로, 기존 참모 납품 약속을 실제 생산라인·지역 물류·도착 영수증·담당자 화면과 연결했다. 별도 목표 장부, 재고, 보상 시스템은 만들지 않았다.

국정 단계에서 `지휘부 → 이행 목표 → 목표 카드 → 생산·수송 경로 추적`으로 연다. 조직 운영과 산업의 기존 이행 약속 화면에도 같은 추적 기능이 제공된다. 지휘부의 생산·창고·인사 기관에서도 연결된다.

## 사용자가 판단할 수 있는 것

- 해당 생산라인의 현재 배정과 효율.
- 같은 품목의 현재 창고·출발 예약·운송 중 물량.
- 약속 기간에 실제로 인정된 생산 완료 또는 국가 가용 편입 실적.
- 경로 차단·출발 예약·기한 검증 등 현재 확인할 다음 작업.
- 정확한 생산라인, 진행 중 운송, 원본이 남아 있는 실제 도착 건, 동일 재임기의 담당자.

추적 내용은 카드를 펼칠 때만 계산·렌더링한다. 상세 기록을 모두 처음부터 펼쳐 놓지 않는다. React 지침에 따라 화면용 수량은 현재 엔진 기록에서 계산하며, 별도 저장 상태나 동기화 효과로 복제하지 않았다.

## 반드시 구별한 상태

`계획/배정 ≠ 생산 완료 ≠ 창고 비축 ≠ 출발 예약 ≠ 운송 중 ≠ 실제 도착 ≠ 기한의 약속 성공`

공장 완료 목표는 해당 라인의 실제 완료 영수증만 센다. 국가 가용 목표는 기간 중 신규 직납과 실제 수송 도착을 센다. 기존 비축을 달성량으로 넣지 않고, 생산 완료와 도착을 더해 이중 집계하지 않는다. 목표 수량을 먼저 채워도 기한의 동일 담당자 검증 전에는 성공을 확정하지 않는다.

현재 지역 창고에서는 생산 묶음이 섞이며 개별 생산 묶음 식별자가 없다. 따라서 같은 품목의 수송을 특정 생산라인이나 참모가 만든 물량으로 단정하지 않는다. 현재 창고·예약·운송량은 목표 전용 물량이 아닌 참고 현황이다.

## 정확한 이동과 권한

- 대상 ID가 없거나 중복되거나 다른 국가이면 임의의 첫 생산라인·후임자·유사 운송으로 이동하지 않는다.
- 도착 증빙은 정확한 수송 ID뿐 아니라 국가·품목·수량·도착 주차·완료 상태가 일치해야 연결한다.
- 담당자가 퇴임·교체·재임용된 경우 과거 약속을 새 재임기에 연결하지 않는다. 화면과 App 이동 처리 양쪽에서 확인한다.
- 끝난 약속의 결과를 현재 창고나 배치 상태로 설명하지 않는다.
- 미래 영수증은 과거 시점의 실적에서 제외한다. 상세 원배송 기록이 없으면 저장된 실적은 보존하되 상세 링크를 제거한다.
- 열람·이동은 지시·예약·보상을 실행하지 않는다. 목적지의 기존 승인과 실행 직전 권한 검사를 유지한다.
- 상신/보고 보직에는 편집 화면을 약속하지 않고 `생산 보고·상신 확인` 또는 `생산 보고 열람`으로 안내한다.

## 검증

### 자동 검증

모델·패널·약속·지휘부·생산·조직·물류 탐색의 통합 회귀 테스트는 **10개 파일 199개 테스트 모두 통과**했다. `npm run lint`와 별도 검증 화면의 TypeScript 검사도 통과했다. GitHub Pages용 빌드는 권한별 문구 수정 전에 한 차례 통과했으며, 최종 문구까지 포함한 재빌드 결과는 작업 완료 메시지에 기록한다.

### 브라우저 부분 엔진 검증

로컬 `http://127.0.0.1:4197/scripts/verify-delivery-goals.html`에서 실제 게임 컴포넌트와 생산·지역 물류·약속 엔진을 조작했다. 사용자 저장은 읽거나 쓰지 않는다. 국가 전체의 세금·전투·참모 성장 결산을 실행한 테스트는 아니다.

| 단계 | 실제 확인 |
| --- | --- |
| 시작 | 국가 기존 비축 100, 창고 20, 출발 예약 20, 약속 실적 0/20 |
| 경로 차단 후 1주 | 약속 실적 0 유지, 현재 차단 사유 표시 |
| 초기화 후 제103주 | 운송 중 20, 약속 실적 0 유지 |
| 제104주 도착 | 국가 가용 120, 약속 20/20, 기한 전 성공 미확정 |
| 제105주 검증 | 목표 충족 확정, 추가 보상 없음 |
| 원배송 상세 숨김 | 약속 실적 유지, 도착 상세 링크 제거 |
| 2주 과거 보기 | 미래 영수증 제외, 완료 판정 검증 불가 |
| 결재권 잠금 | 새 출발 예약 버튼 비활성 |
| 이동 요청 | 정확한 생산라인 `rifle`, 운송 `fixture-shipment:britain:1`, 담당자 `chief-armaments` / `britain-lyttelton` 확인 |

1080p·1440p·4K에서 DOM 경계와 카드/버튼의 가로 넘침을 확인했으며 새 추적 영역의 넘침은 0건이었다. 키보드 Tab으로 다음 생산라인 버튼에 접근했다. 1080p·1440p 스크린샷을 확인했다. 4K 스크린샷 캡처는 도구 오류로 실패했으므로 4K 시각 검증 완료로 간주하지 않는다. 브라우저 콘솔 경고/오류는 없었다. 실제 게임 루트의 국가 선택 화면도 로딩과 콘솔 오류 없음을 확인했으며, 저장 캠페인은 변경하지 않았다.

## 미술과 적용 범위

힉스필드 지침을 검토했다. 이번 작업은 기존 기관 미술을 재사용하고, 변하는 수량·상태·아이콘을 코드로 표시하는 것이 적합해 새 생성 요청을 보내지 않았다. 생성 크레딧을 사용하지 않았다.

이번 묶음은 로컬 구현과 검증이다. 커밋·푸시·배포는 실행하지 않았다. 빌드에 기존 대형 번들 경고가 남아 있으며 이번 변경이 전체 게임 성능 문제를 해결했다고 주장하지 않는다.

## 다음 연결 작업

국가 도착과 특정 부대 수령을 잇기 위해서는 생산 묶음, 재고 귀속, 부대별 실제 수령 기록이 필요하다. 이 기반 없이 이번 목표 추적을 ‘특정 기갑부대까지의 완전한 공급망’으로 표현하지 않는다. 후속 묶음은 이 실제 기록 기반의 부대 수령 또는 참모 면담 후 결과 비교 중 하나를 독립적으로 완결하는 것이 적합하다.
